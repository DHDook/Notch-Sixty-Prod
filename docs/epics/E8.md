# E8 Routing matrix and crossovers

**Status:** Merged: S1–S10 (#244–#255), optimizer-core-synth (#254), B1–B3 (#256, #258, #259), A1 (#257), plan (#260), A2a–A2c (#261–#263).

Open owner decision: accept the S7 review (video-mode IIR fallback implemented as proposed).
## Goal

Replace the fixed Mains+Sub / Bi-Amp / Tri-Amp modes with a source-to-output routing matrix and a
per-output filter chain that renders in the unified graph on any layout, at every rate from 44.1
to 384 kHz. Crossovers come from a filter library (Butterworth, Bessel and Linkwitz-Riley at 6–48
dB/oct, asymmetric slopes, Linkwitz transform) as IIR or linear-phase FIR, with any number of ways
per speaker, up to 8 subwoofers, driver linearisation from near-field captures, an advanced
pipeline view and CamillaDSP YAML import. Existing bi/tri-amp profiles migrate automatically.
Done when every slice passes its deterministic tests at all eight rates; bench checks go to E22.

## Design note

1. **Model.** A new `SpeakerRoutingConfiguration` (Swift, `PlaybackSystemState.speakerRouting`,
   optional, schema 1) replaces modes, buses and per-bus processing. Sources are the program
   layout's lanes plus the bass-managed sub lanes. Each **speaker** has a source and 1–8 **ways**;
   each way has a `PhysicalOutputEndpoint`, a high-pass and a low-pass `FilterSpec`, IIR or FIR
   realisation, up to 16 driver EQ sections, trim, polarity, delay (fractional) and an optional
   limiter. A power-user **matrix** adds raw entries (source lane, output, gain) on top of the ways
   for sums and splits. Templates "Mains + Sub", "2-way" and "3-way" build the common cases. No
   legacy type names are reused.
2. **Filter library** (C++20, `core/src/xover/`, `core/include/n60/xover.h`,
   `N60_XOVER_ABI_VERSION 1`, offline, double precision, no Apple frameworks). `FilterSpec` =
   family {Butterworth, Bessel, Linkwitz-Riley}, order (BW and Bessel 1–8, LR 2/4/6/8, so 6–48
   dB/oct), corner Hz. Bessel is normalised to −3 dB at the corner. HP and LP are independent, so
   slopes may be asymmetric. Linkwitz transform: (f0, Q0) to (fp, Qp). The core designs sections by
   bilinear transform with prewarp at the corner and evaluates complex responses for UI and
   prediction. The graph stages call the same code, so prediction equals render.
3. **Graph position (ABI v17).** Two new kinds:
   - `N60_STAGE_ROUTE` (position 23.5: after PAUSE_GATE, before DELAY). A sparse matrix: for each
     destination lane, up to 8 (source lane, gain) entries. Gains are live and ramped over 5 ms;
     the entry set is topology. Source lanes that are not destinations are cleared. Room
     correction, dynamics, image stages and output gain therefore act per speaker; delay and
     protection act per driver (open question 1).
   - `N60_STAGE_XOVER` (position 23.6, per lane): HP spec, LP spec, optional Linkwitz transform, up
     to 16 EQ sections, trim and polarity. Hz, dB, Q, trim and polarity are live (coefficient
     crossfade as PEQ); family or order changes are a rebuild with the 20 ms fade. Latency 0.
   - S7 adds `N60_STAGE_DRIVER_FIR` (position 23.7), the ROOM_FIR / ROOM_FIR_TWO_BAND implementation
     at a post-route position, for linear-phase crossovers and linearisation.
   - BASS_MGMT gains optional HP/LP `FilterSpec` params for the mains/sub split; the default stays
     LR4 and bit-identical to v16.
   - Graphs with routing are built with `outputChannels` = program lanes + sub lanes + way lanes
     (≤ 64). The engine never reads the flag.
4. **Live path.** With the flag on and routing enabled, every session (stereo included) is an
   N-channel graph session: stereo is a 2-lane layout with expanded output lanes, and the stereo
   bridge splitter is unused. `LiveNChannelOutputRoutePlan` generalises to "graph output lane to
   physical channel", across same-device and aggregate outputs, with the graph-path cap raised to 64
   physical channels. Enabling or disabling routing is a session-kind change (E6 D6 fade). Under
   `e6.legacy-kernel`, routing is refused with a reason and today's splitter keeps working.
5. **Latency alignment.** The Swift compiler adds DELAY and FRAC_DELAY per output so every
   physical output has the same total latency (graph latency report = max); user driver delays add
   on top. Delays stay within `N60_GRAPH_MAX_DELAY_FRAMES` at 384 kHz.
6. **Linear-phase FIR.** The way's magnitude is the IIR prototype's |H| (LR magnitudes sum to
   exactly 1); the core synthesises zero-phase taps by IFFT, centred and windowed, ported from the
   Speaker Optimizer synthesiser with a parity test, and the Speaker Optimizer then calls the core
   version. Taps above 32,768 use the two-band form. The UI shows summed ripple and added latency.
   In E10's video mode linear-phase ways fall back to their IIR equivalent (open question 3).
7. **Driver linearisation.** From a way's near-field capture (and an optional gated far-field
   capture above the merge frequency), design an inverse within the way's passband ±1 octave at
   1/6-octave smoothing, capped at +6 dB boost and never boosting below the way's HP corner (open
   question 6). Minimum-phase by default, linear-phase when the way is FIR; convolved into the
   way's DRIVER_FIR. Prediction is shown; deploy follows the existing prediction verifier.
8. **Subwoofers.** The Swift sub limit becomes 8 on the graph path (one constant shared with
   `UnifiedGraphConfiguration.maxSubwoofers`), decoupled from the frozen legacy C define; the legacy
   kernel refuses more than 4 with a reason (open question 4).
9. **Migration.** On load with the flag on, `mainsSub` / `biAmp` / `triAmp`, the enabled routes and
   per-bus processing become a `SpeakerRoutingConfiguration` (LR24 to LR order 4, LR48 to order 8;
   lower/upper corners kept; trim, polarity, delay, EQ and limiter kept). Legacy fields stay
   readable and written until S10 so flag-off keeps working. Migration is pure and deterministic.
10. **CamillaDSP.** Import a subset (`filters`: Biquad, BiquadCombo LR/BW, Gain, Delay; `mixers`;
    `pipeline`) into the routing model and program PEQ, with a warning for each unsupported item
    (Conv, Dither, Loudness, unknown keys). Parsing uses an in-house YAML-subset reader (open
    question 2). Export grows to mixers, crossovers, per-output filters and delays; round trip is
    exact for supported items.

### Design note (A2–A4)

1. **What "legacy fields" means.** `bassManagement.physicalOutputMode`, `upperFrequencyHz`, `upperTopology`,
   `outputRouting` and `speakerDriverProcessing`. After A2a no UI or start step writes them; they stay in
   `PlaybackSystemState`, Codable and settable in code, and the migration reader and the frozen kernel's splitter
   keep reading them. `bassManagement.enabled`, `frequencyHz` and `topology` are not legacy and keep their editors.
2. **Replacements.** The routing editor (S6, A1 templates, B3) replaces the picker, the upper-crossover editors,
   the bus route editor and the per-bus driver editors. A profile whose legacy routing did not migrate
   (`SpeakerRoutingMigration.Refusal`) shows a read-only summary with one action, "Turn off legacy routing", which
   writes only `outputRouting.enabled = false` (the one legacy write kept, because it removes a blocked state).
3. **Start steps.** The topology preset writes only `enabled`, `frequencyHz` and `topology` and never touches
   `physicalOutputMode`; a stored value is left as it is. The 2.1 step points to the Mains + Sub template for outputs.
4. **Lab on routed ways (26 Oct decision 1).** A new target `.protectedRoutedWay(UUID)` replaces
   `.protectedDriverBus`. Readiness is `protectedWayReady` plus a resolvable physical endpoint. The controller
   renders with the S5 compiler, binds the way's `PhysicalOutputEndpoint` to a carrier route plan and physical
   channel (same-device and aggregate), and plays through the existing protected transport factory. The 1.5×
   guard band, the required limiter, the input-peak ceiling and the re-read of the selected system immediately
   before hardware start all stay; any change to the way after compilation aborts. Provenance records the way as
   rendered (`SpeakerRoutingProtectedExcitation.way`). The same path unblocks live acquisition for B2's
   `driverNearField` on `.routedWay` (26 Oct decision 2): passband-limited sweep, way limiter on, level held to
   −48 to −24 dBFS; `routedWayAcquisitionUnavailable` remains only for an unknown or unready way.
5. **Analysers on way pairs.** PEQ, timing/polarity, crossover-sum and commissioning take a way or an adjacent
   way pair (`adjacentWayPairs`) and the crossover corner from the ways' filter specs, not from
   `frequencyHz` / `upperFrequencyHz`. Commissioning applies to the way's EQ, delay, polarity and trim through the
   routing store; it never writes `speakerDriverProcessing`. Stored bus-keyed commissioning drafts are mapped to
   ways with the S5 bus-to-way identifiers; drafts that cannot be mapped stay readable and are shown as not
   applicable. Reports name ways instead of buses.
6. **Subwoofer limit.** One Swift constant pair: `SubwooferLimit.graph = UnifiedGraphConfiguration.maxSubwoofers`
   (8) and `SubwooferLimit.legacyKernel = N60_MAX_SUBWOOFER_OUTPUTS` (4, frozen). Structure validation and decode
   accept up to 8, so no stored profile is lost. On the graph path a non-routed profile compiles its map as a lane
   map (program lanes then sub lanes to physical channels, up to 64) with a new C compile beside
   `N60LiveNChannelOutputMapCompileRouted`; the legacy compile is unchanged. Session start on the legacy kernel with
   more than 4 subs throws `tooManySubwoofersForLegacyKernel(count)`: "The legacy render kernel drives at most 4
   subwoofers; this profile has N." No silent truncation. Route-plan arrays size to the profile's count, not the define.
7. **Multi-sub tools (26 Oct decision 3).** A3 makes calibration, the multi-sub optimiser and coherent alignment
   refuse more than 4 subs with a named reason instead of truncating; A4 then extends them to 8. The offline
   designers get their own limit, `N60_CALIBRATION_MAX_SUBWOOFERS` (8), decoupled from the frozen
   `N60_MAX_SUBWOOFER_OUTPUTS`, so the legacy kernel and its bass-management snapshot do not change; the C++
   migration of these designers stays with E21. Results for subs 5–8 apply only on the graph path (A3's
   legacy-kernel refusal covers the rest). Sub-to-sub coupling in the optimiser search covers every pair, so its
   cost grows with the count; it stays offline and bounded by a stated iteration cap.

## Follow-up A5: routing editor completion

Asked for by the owner (27 Oct 2026) after an audit of the routing editor. UI and pure view-model logic only.

### What exists today (A5)

- **Speakers**: `SpeakerRoutingEditorModel.addSpeaker` (`Audio/Routing/SpeakerRoutingEditorModel.swift:76`) and
  `setSource` (:85) are called by no view; the only way to get speakers is a template or a CamillaDSP import.
  `removeSpeaker` (:81) has no guard, and the card's "Remove speaker" (`UI/ProductionRoutingEditorView.swift:117`)
  can empty the configuration, which an enabled routing then fails with `.noSpeakers`.
- **Subwoofers**: there is no add or remove control in the routing editor; sub speakers come only from templates.
  The context's sub count is `max(profile subs, configuration.subwooferSourceCount)`, read once in the view's `init`
  (`ProductionRoutingEditorView.swift:13–25`); `@StateObject` keeps that first value, so the matrix rows
  (`matrixSources`, model :252), validation and `applyTemplate(_:deviceUID:)` (:59–72) do not follow a later profile,
  program layout or device-rate change. The sample rate (and so the plots) is frozen the same way.
- **No Output Device Profile editor exists.** Nothing outside tests builds `PhysicalSubwooferOutputAssignment` or
  `OutputDeviceProfileConfiguration`; System Setup only edits calibration on existing assignments
  (`State/SystemSetupMeasureAlign.swift:178–201`, `State/SystemSetupBassCorrect.swift:122–137`) through
  `ProductProfiles.replaceSelectedSystemOutputDeviceProfile` (`State/ProductProfiles.swift:1496`), which validates the
  structure and refuses while legacy `outputRouting` is on. Validation already accepts 8 subs
  (`Routing/OutputDeviceProfileConfiguration.swift:379`); coherent-alignment records validate against the profile's
  subs (:440–456), so changing the subs can make an otherwise valid profile fail.
- **Outputs**: a way row shows "Output n" as text only (`ProductionRoutingEditorView.swift:134`). "Add way" picks the
  first channel index unused on any device, capped at 64 and ignoring the device's `outputChannelCount` (:109–111).
- **Linear phase**: `RoutedWay.realisation` (`.iir` / `.fir`, `Routing/SpeakerRoutingConfiguration.swift:37, :59`) is
  honoured by the compiler, which gives a speaker's filtered FIR ways one shared group delay
  (`UnifiedGraph/SpeakerRoutingCompiler.swift:93–112, :139`) and falls back to IIR in low-latency mode; the plan comes from
  `CrossoverCore.linearPhasePlan` (`CrossoverCore.swift:135`). The editor has no control, and its plots
  (`wayResponse`, `summedMagnitudeDB`, model :334–362) always use the IIR phase.
- **Routed sessions**: the routing owns every physical output; the profile supplies only the program layout
  (`Audio/AudioIOEngine.swift:4630–4640`). Activation refuses subs with bass management off and bass management with
  no sub source (:4583–4593). An output or sub-count change reconfigures with the shutdown fade; other edits are live
  (:4600–4621). A refused commit leaves the engine unchanged but the model keeps the refused configuration (view :47–54).

### Design note (A5)

1. **Live context.** The model gains `updateContext(programLanes:profileSubwoofers:sampleRate:)`; the view calls it
   from `.onChange` of the engine's published profile and selected device. `context.subwoofers` is recomputed after
   every edit as `max(profileSubwoofers, configuration.subwooferSourceCount)`. The model is never re-created.
2. **Refused commits revert.** When `replaceSpeakerRoutingConfiguration` throws, the view calls a new
   `model.revert(to: engine.speakerRoutingConfiguration)`, which sets the configuration without `onCommit`, drops
   bypassed linearisations for ways that no longer exist, and the error stays shown. Guards below avoid most refusals.
3. **Free outputs.** One pure helper, `nextFreeEndpoint(deviceUID:channelCount:)`, returns the lowest channel of that
   device not used by any way or raw matrix entry, or nil when all are taken. "Add way", "Add speaker" and "Add
   subwoofer" use it on the speaker's device (else the selected output); nil gives "All n outputs of <device> are in
   use."
4. **Add speaker.** Source: the first program lane no speaker reads, else lane 0. Name: the profile's role name for
   that lane when an enabled profile gives one, else Left/Right on stereo, else "Speaker n". One unfiltered way on the
   next free output. Each speaker header gets a source picker (program lanes, then subs) wired to `setSource`.
5. **Last speaker.** `removeSpeaker` returns Bool and refuses the last speaker while routing is enabled (the button is
   disabled with "Turn off the routing matrix to remove the last speaker"); with routing off it may empty the list.
6. **Subwoofers in the routing editor.** A "Subwoofers" row lists sub speakers with "Add subwoofer" up to
   `SubwooferLimit.graph` (8). A new sub is "Sub n", source `.sub(n − 1)`, one unfiltered way (bass management filters
   the sub lanes, and the Mains + Sub template detection stays intact). Removing sub k renumbers higher sub sources,
   in speakers and raw matrix entries, down by one so the sources stay contiguous. While routing is enabled, adding
   the first sub with bass management off and removing the last sub with it on are disabled with the engine's reason.
   Routing subs do not write the profile: in a routed session the routing owns the outputs.
7. **Profile subwoofers card.** A small new card on the Speakers tab, shown when the selected Playback System has an
   enabled Output Device Profile: Sub 1…n with an output picker, add (to 8) and remove, through
   `replaceSelectedSystemOutputDeviceProfile`. Indices stay contiguous from 0 and each sub keeps its own calibration.
   Pure logic lives in a new `OutputDeviceProfileSubwooferEditing` extension (new file; `OutputDeviceProfileConfiguration.swift`
   is not edited). A change that makes a stored record fail `validate(profile:)` (coherent single- or multi-sub alignment,
   calibration summary, Speaker Optimizer PEQ/FIR) clears that record, after a confirmation that names each one;
   records that still validate are kept. With more than 4 subs and the unified graph off, the card says the legacy
   kernel drives at most 4 (A3 refuses at session start). With routing enabled it says the routing owns the outputs.
   Add/remove follow bass management as in note 6 (the store's validation refuses otherwise).
8. **Output reassignment.** Each way row gets an output picker: every connected device's channels by name
   ("<Device> · Out n", up to `outputChannelCount`), plus the current endpoint marked "not connected" if its device is
   absent. `setEndpoint(_:way:speaker:)` returns `.moved`, `.swapped(wayID)` or `.unchanged`: an endpoint already used by
   another way swaps the two in one edit and one commit. Raw matrix entries stay on their physical output; a way's
   linearisation stays with the way (the driver did not change). The same picker serves the profile card.
9. **Linear phase per speaker.** The speaker header gets "Minimum phase (IIR) / Linear phase (FIR)", which sets
   `realisation` on all of its filtered ways (`setRealisation(_:speaker:)`); a stored speaker with mixed values shows
   "Mixed" until a choice. Hidden for a speaker with no filtered way (sub speakers). Next to it: the added latency at
   the current rate (the speaker's shared group delay from `linearPhasePlan`, the same value the compiler uses) and
   "two-band" when the plan is two-band, plus the caption "Plays as minimum phase in low-latency mode". The plot shows
   FIR ways at their magnitude with zero phase (the shared delay removed), so the drawn sum is the linear-phase sum.
10. **Captions.** "Changing outputs or subwoofers restarts the output with a short fade" under the template card.
