## Goal

A user can export the loudspeaker chain that is running now in one action. The targets are a WAV
convolution set, an Equalizer APO configuration, and miniDSP biquad and FIR files. Each export
names the parts it cannot carry. When the device's physical format is 16-bit integer, the output
gets TPDF dither automatically; no other output does.

## What exists today

- **Preset exports (stereo EQ only).** `PresetInterchange` (`NotchSixty/UI/ProductionProfileToolbar.swift:644`)
  exports REW text, EasyEffects and CamillaDSP YAML from `StereoEQConfiguration` (`:980`, `:1068`,
  `:1135`). The menu is at `:220`, `NSSavePanel` at `:588-589`, warnings in
  `PresetInterchangeExport` (`:613`), tests in `PresetInterchangeTests.swift`. These exports
  carry no FIR, crossovers, delay, routing or bass management.
- **Parsers.** `EqualizerAPOPresetImporter` reads `Preamp:` and `Filter N: ON PK/LS/HS` lines
  (`Audio/Routing/HeadphoneResponseFitting.swift:460-511`). `MeasurementFormats.decodeWAV` reads
  PCM 16/24/32 and float 32 (`Audio/MeasurementFormats.swift:171-176`). The app has no WAV writer
  and no miniDSP code.
- **The running chain can be read off the render thread.** `AudioIOEngine.headroomSpecSnapshot()`
  (`AudioIOEngine.swift:3018`) returns the published `UnifiedGraphSpec`
  (`UnifiedGraph/UnifiedGraphSpec.swift:166`), and the E9 headroom model walks it off the main
  actor (`OutputHeadroomModel.swift:89-110`). Stage kinds and positions are listed in
  `core/include/n60/graph.h:59-132`.
- **Design maths.** Crossover biquads, their responses and FIR crossovers come from `n60/xover.h`
  (`:89-229`). The PEQ RBJ design exists only inside the core (`core/src/snapshot.hpp:105`) and
  has no public entry point.
- **Dither.** None anywhere. The chain ends PROTECTION (27, the last audio-modifying stage),
  DELTA_SUBTRACT (27.5), MUTE (28), ANC_CAPTURE (29), FINAL_SANITISE (30), FINAL_METER (31)
  (`graph.h:89-93`, `:129`).
- **Device format.** Only the virtual format is read (`CoreAudio/CoreAudioError.swift:565`,
  wrapper `:34-44`). The app sets float32 on its own streams
  (`CoreAudioNChannelTransportSession.swift:841-849`). `AudioOutputDevice`
  (`Devices/AudioOutputDevice.swift:17-46`) holds sample rates only, and the physical format is
  never read.
- **Sandbox.** `files.user-selected.read-write` (`NotchSixty.entitlements:11`) covers folder
  writes from a panel. Flags live in `FeatureFlag.all` (`State/FeatureFlags.swift:21`).

## Design note

1. **One source.** Exports read `headroomSpecSnapshot()`, which is exactly what the core renders,
   and never read UI models. With no graph running, or with the legacy kernel, Export is disabled
   and says why. Exports run in a detached utility task and never touch the render thread or
   engine state.
2. **Stage classes.** `FilterExportPlan` puts each stage in one of three classes:
   - **Exported (linear, time-invariant):** GAIN, PEQ (including M/S encode and decode), FIR,
     BASS_MGMT, STEREO_CROSSOVER, ROOM_FIR, ROOM_FIR_TWO_BAND, SPEAKER_IR, SYMMETRY, OUTPUT_GAIN,
     ROUTE, XOVER, DRIVER_FIR, DRIVER_FIR_TWO_BAND, LANE_DELAY, DELAY, FRAC_DELAY, and the
     headphone PEQ (Q4).
   - **Excluded, each with a named reason:** the dynamics family, AMBIENT, IMAGE, CROSSFEED,
     CROSSTALK, BINAURAL, PAUSE_GATE, EXTERNAL and PROTECTION. For PROTECTION the export adds "set
     a limiter on the target".
   - **Never exported:** the ANC stages and MIMO. Exporting them would run anti-noise or MIMO
     treatment outside their authorisation paths.

   Meters, taps, sanitisers, mute, generator and delta stages are ignored. The export sheet lists
   the excluded stages before the user saves.
3. **Impulses come from the real engine.** `ExportImpulseRenderer` builds a private core graph
   from the spec without the excluded stages. It feeds a unit impulse into each input and records
   every output, giving an input × output matrix at the live rate, so the prediction equals the
   render.
   - **Length:** the smallest power of two that holds the response down to a -140 dB tail,
     between 4,096 and 2^20 frames. A length the user fixes truncates with a half-Hann fade over
     the last 1% and adds a warning.
   - **Leading silence:** trimmed by the same count on every output, so relative delays survive.
     The manifest records the trimmed latency.
4. **Other rates.**
   - **WAV sets:** at a rate other than the live rate, the rendered impulses are resampled with
     E7 S2's `n60/resample.h`. Content above the source Nyquist is empty, and the manifest says so.
     Only the live rate is offered until E7 S2 merges.
   - **Parametric targets** (APO filters, miniDSP biquads) are redesigned from the stage
     parameters at the target rate.
   - **Type-9 Linkwitz sections** store only prepared coefficients. At another rate they go into
     the FIR part; on miniDSP they are refused with a reason.
5. **Headroom.** One common gain, which keeps the inter-channel balance, brings max |H(f)| over
   all paths from 20 Hz to 20 kHz to -0.5 dB. It uses the E9 headroom rule. The gain is written as
   the APO `Preamp:`, the miniDSP input gain, or baked into the WAV set, and recorded in the
   manifest.
6. **WAV writer.** `WAVFileWriter` is pure Swift with no dependency. It writes float 32 (the
   default) or PCM 24 with TPDF at the 24-bit LSB, uses `WAVE_FORMAT_EXTENSIBLE` with a channel
   mask above two channels, and refuses files over 4 GiB.
7. **WAV convolution set.** Each export is a folder:
   - `<rate>/<channel>.wav` when each output depends on one input;
   - `<rate>/<input>_to_<output>.wav` (a matrix) when any output mixes inputs, as bass
     management, M/S or routing do. An option writes one interleaved file per input instead;
   - `README.txt`, which records channel order, rate, gain, latency, format, excluded stages and
     the app version.
8. **Equalizer APO.** The export is a folder with `NotchSixty.txt` (included from `config.txt`)
   and an `ir/` folder.
   - **Channels:** `Channel:` blocks use APO channel names. PEQ is written as `PK`, `LSC` and
     `HSC`. Crossovers are written as `LP`/`HP` sections, each with its own frequency and Q from
     the prototype, so APO redesigns them at its own rate.
   - **Delay, polarity and summing:** `Delay: x ms`. Polarity and bass-management sums are
     written as `Copy:` terms.
   - **FIR stages:** written as `Convolution: ir/<channel>.wav`.
   - **Refusals:** an output whose input paths are filtered differently is refused, and the
     message points to the WAV set.
   - **Option:** "convolution only" writes one WAV per channel and nothing else.
9. **miniDSP.**
   - **Device table:** a static `MiniDSPDeviceProfile` table (Q2) holds rate, biquads per channel,
     FIR taps and coefficient range.
   - **Coefficients:** a new offline core entry, `n60/export.h` `n60_export_peq_biquad`, wraps the
     internal RBJ design, so exported coefficients are bit-identical to the live ones at the same
     rate. Crossovers come from `n60_xover_design`.
   - **Biquad files:** each channel is a text file in miniDSP's advanced-biquad format, with a1
     and a2 sign-flipped to miniDSP's convention (source: miniDSP's public "Advanced biquad
     programming" note, cited in S3).
   - **FIR files:** one coefficient per line, within the device's tap budget.
   - **Over budget:** the export refuses and names the count needed against the device budget
     (Q3).
   - **Hand entry:** delay, gain, polarity and routing go to `settings.txt` for the user to enter
     by hand.
10. **Dither stage.** N60_STAGE_DITHER sits at position 30.5, after FINAL_SANITISE and before
    FINAL_METER, so the meter shows what the device gets. Params are the bit depth (8–24) and a
    lane mask.
    - **Processing:** for each masked lane, y = x + (u1 − u2)·q with q = 2^-(bits−1) (TPDF, ±1
      LSB). The result is rounded to the q grid and clamped to [−1, 1 − q]. Because the stage
      quantises, the HAL's float-to-integer conversion is exact whether the HAL rounds or
      truncates.
    - **Random numbers:** one xoshiro128+ generator per lane, seeded from the lane and a per-build
      seed.
    - **Silence:** an all-zero block outputs zero (Q1).
    - **Realtime properties:** no allocation or locks, zero latency, independent of rate; reset
      reseeds.
    - **ANC:** ANC_CAPTURE (29) comes before the stage, so the Quiet Zone never sees dither.
    - **ABI:** the version bumps.
11. **When dither turns on.** `DevicePhysicalFormatReader` reads
    `kAudioStreamPropertyPhysicalFormat` on each output stream of the selected device and listens
    for changes. A change rebuilds the snapshot; it does not restart the transport.
    `AudioOutputDevice` gains `physicalFormats`.
    - **Lane mask:** Swift sets the mask to the lanes whose device channel is on a signed-integer
      stream of 16 bits or fewer (Q5) and publishes `UnifiedGraphConfiguration.dither` from every
      builder (stereo, N-channel, routed, binaural). The core never reads the flag.
    - **UI:** the Outputs device row and Diagnostics read "16-bit integer · dither on (TPDF)".
    - **Not covered:** there is no user switch (Q6), and measurement transports do not dither (Q7).

## Feature flag

`e17.export` gates the export sheet and menu (S2, S3). `e17.dither` gates publishing the DITHER
stage (S4), which changes what plays. S1 has no user surface and needs no flag. Only Swift reads
the flags. S5 removes both.

## Bench checks (deferred to E22)

- **Equalizer APO:** on Windows, a loopback of the parametric and convolution-only exports
  (stereo and 2.1) matches the Notch Sixty live render within 0.2 dB from 20 Hz to 20 kHz at 44.1
  and 48 kHz.
- **miniDSP:** each Q2 device's plug-in accepts every exported file, and the measured response
  is within 0.3 dB of the prediction.
- **WAV set:** in one convolution host (Q4), the loopback null against Notch Sixty live reaches
  -60 dB or better at each rate the host supports.
- **Dither on a 16-bit DAC:**
  - the loopback is bit-exact to the stage output, which confirms the HAL's scale;
  - a -110 dBFS sine plays clean;
  - an idle device is silent;
  - switching 24 → 16 → 24 bit in Audio MIDI Setup while playing switches dither with no glitch;
  - a 24-bit or float device gets no dither;
  - Quiet Zone attenuation is unchanged with dither on.

## Open questions for the owner

1. **Q1 Dither on digital silence.** Should an all-zero block output zero, or should dither run
   all the time? Recommended: output zero, so an idle 16-bit DAC stays silent; the switch happens
   only at exact silence.
2. **Q2 Which miniDSP devices for v1.** Recommended: 2x4 HD and Flex for biquads, plus SHD and
   Flex Eight for FIR if their plug-ins import coefficients. Exclude DDRC models, because Dirac
   locks their filter blocks.
3. **Q3 What happens when miniDSP is over budget.** Refuse with the count, or drop or merge bands
   automatically? Recommended: refuse and list the bands. Silent merging changes the sound.
4. **Q4 Scope and hosts.** Should headphone PEQ go into the APO and WAV exports (crossfeed and
   binaural stay out), and which convolution hosts should the WAV set target? Recommended:
   include headphone PEQ. Ship generic per-channel and matrix WAVs, checked on CamillaDSP, JRiver
   and Roon, with no host-specific packaging in v1.
5. **Q5 Which formats get dither.** Integer formats of 16 bits or fewer, or exactly 16 as the
   program plan says? Recommended: 16 bits or fewer; never 20 or 24 bits, never float.
6. **Q6 User control.** Automatic only, or an Off/Auto/Always setting? Recommended: automatic
   only, with a developer-menu override for testing.
7. **Q7 Measurement and the old exports.** Should measurement transports stay undithered, and
   should the REW, EasyEffects and CamillaDSP stereo-EQ exports stay as they are? Recommended:
   yes to both. Sweep levels keep 16-bit error below the measurement floor, and the old exports
   have users.
