## Goal

A user can export the loudspeaker chain that is running now in one action. The targets are a WAV
convolution set, an Equalizer APO configuration, and miniDSP biquad and FIR files. Each export
names the parts it cannot carry. When the device's physical format is 16-bit integer, the output
gets TPDF dither automatically; no other output does.

## What exists today

- **Preset exports (stereo EQ only).** `PresetInterchange` (`UI/ProductionProfileToolbar.swift:644`;
  menu `:220`, save panel `:588`) exports REW, EasyEffects and CamillaDSP from
  `StereoEQConfiguration`. It carries no FIR, crossover, delay or routing.
- **Parsers.** `EqualizerAPOPresetImporter` (`Audio/Routing/HeadphoneResponseFitting.swift:460-511`)
  and `MeasurementFormats.decodeWAV` (`Audio/MeasurementFormats.swift:171-176`). There is no WAV
  writer and no miniDSP code.
- **Running chain.** `AudioIOEngine.headroomSpecSnapshot()` (`AudioIOEngine.swift:3018`) returns
  the published `UnifiedGraphSpec` (`UnifiedGraphSpec.swift:166`); the E9 headroom model walks it
  off the main actor (`OutputHeadroomModel.swift:89-110`). Stages: `core/include/n60/graph.h:59-132`.
- **Design maths.** Crossovers: `n60/xover.h:89-229`. PEQ RBJ design is internal only
  (`core/src/snapshot.hpp:105`).
- **Dither.** None anywhere. The chain ends PROTECTION (27, the last audio-modifying stage),
  DELTA_SUBTRACT (27.5), MUTE (28), ANC_CAPTURE (29), FINAL_SANITISE (30), FINAL_METER (31)
  (`graph.h:89-93`, `:129`).
- **Device format.** Only the virtual format is read (`CoreAudio/CoreAudioError.swift:565`); the
  app sets float32 (`CoreAudioNChannelTransportSession.swift:841-849`). `AudioOutputDevice`
  (`Devices/AudioOutputDevice.swift:17-46`) has no physical format.
- **Sandbox.** `files.user-selected.read-write` (`NotchSixty.entitlements:11`) covers panel writes.

## Design note

1. **One source.** Exports read `headroomSpecSnapshot()` (what the core renders), never UI models,
   in a detached utility task. With no graph or on the legacy kernel, Export is disabled with a
   reason.
2. **Stage classes.** `FilterExportPlan` puts each stage in one of three classes:
   - **Exported (linear, time-invariant):** GAIN, PEQ (including M/S encode and decode), FIR,
     BASS_MGMT, STEREO_CROSSOVER, ROOM_FIR, ROOM_FIR_TWO_BAND, SPEAKER_IR, SYMMETRY, OUTPUT_GAIN,
     ROUTE, XOVER, DRIVER_FIR, DRIVER_FIR_TWO_BAND, LANE_DELAY, DELAY, FRAC_DELAY, and the
     headphone PEQ.
   - **Exported to the WAV matrix and APO only (S2b, Q4):** CROSSFEED, the HEADPHONE crossfeed and
     BINAURAL, all static (head tracking off). miniDSP refuses them with a reason.
   - **Excluded, each with a named reason:** the dynamics family, AMBIENT, IMAGE, CROSSTALK,
     PAUSE_GATE, EXTERNAL and PROTECTION. For PROTECTION the export adds "set a limiter on the
     target".
   - **Never exported:** the ANC stages and MIMO (they would run outside their authorisation
     paths). Non-audible stages are ignored; the sheet lists exclusions before saving.
3. **Impulses come from the real engine.** `ExportImpulseRenderer` builds a private core graph
   from the spec minus excluded stages and records an input × output impulse matrix at the live
   rate.
   - **Length:** the smallest power of two that holds the response down to a -140 dB tail,
     between 4,096 and 2^20 frames. A length the user fixes truncates with a half-Hann fade over
     the last 1% and adds a warning.
   - **Leading silence:** trimmed by the same count on every output, so relative delays survive.
     The manifest records the trimmed latency.
4. **Other rates.**
   - **WAV sets:** at a rate other than the live rate, the rendered impulses are resampled with
     E7 S2's `n60/resample.h`. Content above the source Nyquist is empty, and the manifest says so.
     Only the live rate is offered until E7 S2 merges.
   - **Parametric targets** (APO filters, miniDSP biquads) are redesigned from the stage
     parameters at the target rate.
   - **Type-9 Linkwitz sections** store only prepared coefficients. At another rate they go into
     the FIR part; on miniDSP they are refused with a reason.
5. **Headroom.** One common gain brings max |H(f)| over all paths (20 Hz–20 kHz) to -0.5 dB,
   written as APO `Preamp:`, miniDSP input gain or baked into the WAV set.
6. **WAV writer.** `WAVFileWriter` is pure Swift with no dependency. It writes float 32 (the
   default) or PCM 24 with TPDF at the 24-bit LSB, uses `WAVE_FORMAT_EXTENSIBLE` with a channel
   mask above two channels, and refuses files over 4 GiB.
7. **WAV convolution set.** Each export is a folder:
   - `<rate>/<channel>.wav` when each output depends on one input;
   - `<rate>/<input>_to_<output>.wav` (a matrix) when any output mixes inputs, as bass
     management, M/S or routing do. An option writes one interleaved file per input instead;
   - `README.txt`, which records channel order, rate, gain, latency, format, excluded stages and
     the app version.
8. **Equalizer APO.** The export is a folder with `NotchSixty.txt` (included from `config.txt`)
   and an `ir/` folder.
   - **Channels:** `Channel:` blocks use APO channel names. PEQ is written as `PK`, `LSC` and
     `HSC`. Crossovers are written as `LP`/`HP` sections, each with its own frequency and Q from
     the prototype, so APO redesigns them at its own rate.
   - **Delay, polarity and summing:** `Delay: x ms`. Polarity and bass-management sums are
     written as `Copy:` terms.
   - **FIR stages:** written as `Convolution: ir/<channel>.wav`.
   - **Refusals:** an output whose input paths are filtered differently is refused, and the
     message points to the WAV set.
   - **Option:** "convolution only" writes one WAV per channel and nothing else.
9. **miniDSP.**
   - **Device table:** a static `MiniDSPDeviceProfile` table (Q2) holds rate, biquads per channel,
     FIR taps and coefficient range.
   - **Coefficients:** a new offline core entry, `n60/export.h` `n60_export_peq_biquad`, wraps the
     internal RBJ design, so exported coefficients are bit-identical to the live ones at the same
     rate. Crossovers come from `n60_xover_design`.
   - **Biquad files:** each channel is a text file in miniDSP's advanced-biquad format, with a1
     and a2 sign-flipped to miniDSP's convention (source: miniDSP's public "Advanced biquad
     programming" note, cited in S3).
   - **FIR files:** one coefficient per line, within the device's tap budget.
   - **Over budget:** the export refuses and names the count needed against the device budget
     (Q3).
   - **Hand entry:** delay, gain, polarity and routing go to `settings.txt`.
10. **Dither stage.** N60_STAGE_DITHER sits at position 30.5, after FINAL_SANITISE and before
    FINAL_METER, so the meter shows what the device gets. Params are the bit depth (8–24) and a
    lane mask.
    - **Processing:** for each masked lane, y = x + (u1 − u2)·q with q = 2^-(bits−1) (TPDF, ±1
      LSB). The result is rounded to the q grid and clamped to [−1, 1 − q]. Because the stage
      quantises, the HAL's float-to-integer conversion is exact whether the HAL rounds or
      truncates.
    - **Other:** one seeded xoshiro128+ per lane; an all-zero block outputs zero (Q1); no
      allocation or locks, zero latency; ANC_CAPTURE (29) precedes it; the ABI version bumps.
11. **When dither turns on.** `DevicePhysicalFormatReader` reads
    `kAudioStreamPropertyPhysicalFormat` on each output stream of the selected device and listens
    for changes. A change rebuilds the snapshot; it does not restart the transport.
    `AudioOutputDevice` gains `physicalFormats`.
    - **Lane mask:** Swift sets the mask to the lanes whose device channel is on a signed-integer
      stream of 16 bits or fewer (Q5) and publishes `UnifiedGraphConfiguration.dither` from every
      builder (stereo, N-channel, routed, binaural). The core never reads the flag.
    - **UI:** the Outputs device row and Diagnostics read "16-bit integer · dither on (TPDF)".
    - **Not covered:** there is no user control and no override of any kind (Q6), and measurement
      transports do not dither (Q7).
12. **Crossfeed and binaural (S2b).** These are rendered through the same offline graph with the
    head orientation fixed at the reference (0°), giving an N-in, 2-out matrix: 2 × N filters
    (stereo 4, 5.1 12, 7.1 16, 7.1.4 24). Matrix files are named `<input>_to_<L|R>.wav`.
    - **Manifest:** records the layout, the filter count, "static, no head tracking", the
      HRTF/SOFA set name and its licence. Export refuses a set whose licence does not allow
      redistribution (G1).
    - **Matrix hosts:** S2b checks from public documentation how CamillaDSP, JRiver and Roon load
      an N×2 matrix, and how APO expresses one (per-input `Copy:` channels plus convolution).
      Where the generic layout loads, nothing host-specific is written. A host that needs its own
      config file, or a layout APO cannot express, becomes a gap; it is never dropped silently.

## Feature flag

`e17.export` gates the export sheet and menu (S2, S2b, S3). `e17.dither` gates publishing the DITHER
stage (S4), which changes what plays. S1 has no user surface and needs no flag. Only Swift reads
the flags. S5 graduates both.

- **APO:** Windows loopback of parametric and convolution-only exports (stereo, 2.1) within

    float devices get none; Quiet Zone attenuation is unchanged;
  - a DAC that reports 24 bits but resolves fewer (bench only; the app cannot detect it, Q6).

## Owner decisions (PR #473)

1. **Q1** An all-zero block outputs exact zero; dither runs otherwise.
2. **Q2** miniDSP for v1: 2x4 HD and Flex (biquads); SHD and Flex Eight (FIR) if their plug-ins
   import coefficients; no DDRC models.
3. **Q3** Over budget: refuse and list the bands; no automatic merging.
4. **Q4 (changed)** Headphone PEQ is included. Crossfeed and binaural (virtual speakers) are
   exported statically, with no head tracking, to the WAV matrix and APO, and not to miniDSP.
   They have their own slice, S2b. The HRTF/SOFA licence check is G1.
5. **Q5** Dither only integer formats of 16 bits or fewer; never 20 or 24 bits, never float.
6. **Q6 (changed)** Dither is automatic only, with no user control and no developer-menu override.
   A DAC that reports 24 bits but resolves fewer is a bench check in E22.
7. **Q7** Measurement transports stay undithered; the REW, EasyEffects and CamillaDSP exports
   stay as they are.

## Gaps

- G1 [scoped] HRTF/SOFA licence: crossfeed and binaural exports write processed third-party HRTF data into files the user can redistribute. Every bundled or imported set needs a recorded licence that permits this, and the export must refuse any set without one (found in plan review, PR #473; owner slice: S2b)
