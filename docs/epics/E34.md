## Goal

Every page looks and behaves like one app. One written design language, in the macOS 27 Liquid Glass
style throughout (owner, 17 Nov 2026), with shared values and components that every page uses. Menus,
keyboard, accessibility settings, empty and error states, and window sizes follow one rule each.
No feature changes: E34 changes how pages are built and look, never what they do.

## Design note

1. **macOS 27 Liquid Glass throughout (owner, 17 Nov 2026).** The design language is written against the
   macOS 27 human interface guidelines and SDK, not macOS 26. S0 starts by reading Apple's macOS 27
   documentation and records what it finds in `docs/DESIGN_LANGUAGE.md`. Reported macOS 27 changes, from press
   coverage only and not yet checked against Apple's documentation: lower default transparency, one window
   and sidebar corner shape applied by the system, a uniform toolbar, and a user setting that moves glass
   between clear and tinted. Rule: use system containers, shapes and button styles; do not hand-set a value
   the system now supplies. Glass is for controls and navigation that float above content, never for content
   itself.
2. **Shared values and components.** One Swift file of values (three corner radii, one spacing scale, a type
   scale with an 11-point minimum) and a small set of components: card, page header, status badge, button
   roles (primary, secondary, destructive), state view, and value formatters for dB, Hz, ms and percent.
   New files go under `NotchSixty/UI/Design/`.
3. **Status levels.** Four levels (good, attention, problem, off), each with a colour and an icon, so colour
   is never the only signal.
4. **How the flag works.** The components hold two sets of values: today's most common ones and the new
   ones. Pages move onto the components first with almost no visible change; the flag switches the whole
   app to the new look at once. A page that uses unusual values today may shift by a few points when it
   moves, without the flag (decision 7). The owner sees the new look early by switching the flag on in the
   test build.
5. **New page slices.** Once S1 has merged, every page slice in any epic uses the shared components and
   adds no new card helper, hand-set radius or hand-set status colour. Slices that are already built are
   moved by S2 and S3.
6. **No engine work.** Swift UI only. No slice touches the realtime engine or makes `AudioIOEngine.swift` longer.
