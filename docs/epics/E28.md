## Goal

The Dynamics and Meters pages show a listener what each stage is doing, at display rate, on
every output configuration, with the Equalizer page's feel, precision and accessibility, and the
dynamics stages grow into a world-class playback suite: every control that could be useful in
playback, with latency only where the listener turns it on.

## Design note

1. **Testable cores, thin views.** Plain-Swift types with XCTests: `MeterBallistics`, `ClipLatch`,
   `LoudnessMeter`, `SpectrumDisplayProcessor`, `DynamicsTransferCurve`, `GainReductionHistory`,
   `MeterReadbackHub`, `ParameterScale`, plus the generalised E27 types.
2. **One reader per readback.** `MeterReadbackHub` alone calls the read-and-reset readbacks, keeps
   each subscriber's maximum since its last read, and fans out to the Meters page, Dynamics page,
   navigator and sidebar. It polls only while a subscriber is visible (page shown, window not
   minimised or occluded via `NSWindow.occlusionState`) and processing runs.
3. **Drawing.** `Canvas` in `TimelineView(.animation(paused:))`, paused when hidden; data at 60 Hz.
4. **Ballistics.** Peak (instant attack, 20 dB fall in 1.7 s, IEC 60268-18), VU (300 ms to 99 %,
   IEC 60268-17), RMS (300 ms); Peak default, persisted. Hold 2 s. The clip latch sets on any
   over-range sample or true peak above 0 dBTP and clears only on click or Reset. Zones use ticks,
   text ("CLIP", "OVER") and hatching, never colour alone.
5. **Accessibility.** Every meter, curve and bar has an identifier and an `accessibilityValue`
   updated at most every 2 s or on latch. Dynamics controls get labels, values with units,
   identifiers and keyboard stepping, as on the Equalizer page.
6. **Loudness (S2).** ITU-R BS.1770-4 K-weighting per rate by bilinear transform of the analog
   shelf and RLB high-pass, matching the published 48 kHz coefficients; 400 ms blocks, 75 % overlap.
   Momentary, short-term, integrated (−70 LUFS and −10 LU gates), loudness range per EBU Tech 3342,
   presented per EBU R128. True-peak max reuses the engine's 4× protection true peak through the hub.
   Swift, on the analysis worker; Output by default, Input optional; rising `droppedFrames` marks
   integrated "gapped". **Channel weighting:** `LoudnessMeter` takes N channels with semantic
   positions: G = 1.0 for L, R, C and any channel within ±60° azimuth or elevated 30° or more;
   1.41 for 60–120° azimuth below 30° elevation; LFE excluded (BS.1770-4 Table 3). Today the capture
   is two channels, both 1.0, measured after the fold (the card says so); the weighting takes effect
   once loudness is fed more than the stereo capture (G9).
7. **Spectrum (S3).** Smoothing off, 1/24 to 1/3 octave; averaging 125 ms, 1 s, infinite; tilt 0,
   3, 4.5 dB/oct about 1 kHz; freeze; one session reference trace; hover read-out; Input and Output
   overlaid. E27 S2b can reuse `SpectrumDisplayProcessor`.
8. **Parameter feel (S4).** Generalise E27 S1's `EQValueParser`, `EQNudge`, `EQEditHistory` and
   `EQNumberField` into unit-aware `ValueParser`, `ValueNudge`, `EditHistory<State>` and
   `ParameterNumberField`; the EQ names stay as thin wrappers. `ParameterScale` is logarithmic for
   attack, release, hold, lookahead and sidechain HPF (0 Hz "off" at the left stop). Steps: time and
   frequency ×2^(1/12), Shift ×2^(1/3), Option ×2^(1/96); dB 0.5 / 3 / 0.1; ratio ×1.1 / ×1.5 /
   ×1.02. Double-click resets; Option-drag 0.1×; values clamp to the config range (decision 2).
   Undo stores whole-`DynamicsConfiguration` pairs; listen and solo are session state, not undone.
9. **Auto makeup (S4).** Swift only: makeup = −(static curve gain at −18 dBFS) from threshold,
   ratio and knee, rounded to 0.1 dB, clamped. Off by default; persisted.
10. **Transfer curve (S5).** Static gain computer with soft knee (Giannoulis, Massberg and Reiss,
    JAES 60(6), 2012) for compressor, multiband bands, de-esser, expander (floored at its range) and
    limiter; a test pins it to the core stage. S7d adds the expander knee. The live dot sits where
    the curve's reduction equals the readback; at 0 dB no dot is drawn.
11. **Gain reduction (S5).** Bars with 1 s hold, a 10 s history (600 points), a bar on each
    navigator row; `UnifiedGraphHost` gains the expander read.
12. **Compressor extras (S7a).** New parameters [10] mix 0–100 % (default 100), [11] link 0–100 %
    (default 100; detector = link·max(group) + (1 − link)·own lane), [12] detector 0 peak / 1 RMS,
    [13] RMS window 5–200 ms (default 50; one-pole mean square, as the dynamic EQ), [14] lookahead
    frames. Mix and link ramp over 5 ms via the mailbox; detector and window are live.
    **Lookahead:** per-compressor toggle, off by default (no ring, latency 0, so existing profiles
    add none), time 1–10 ms (5 ms when first turned on). On: wet and dry run through a ring of
    round(ms·fs/1000) frames in the snapshot arena; the detector sees the undelayed signal. Toggle
    and time are topology, so the existing rebuild fade makes switching click-free. **Latency
    honesty:** the frames enter the per-lane sum and Swift's `coveredLatency`, like the denoiser and
    the E9 FIR, so the path is denoiser + FIR (256 + declared) + lookahead + protection look-ahead +
    AU rack, and every display and consumer reads that one total (G10).
13. **Expander extras and listen (S7b).** Expander [6] hold 0–500 ms (counter round(ms·fs/1000)),
    [7] knee 0–24 dB (quadratic, mirrored from design 10), [8] detector, [9] RMS window, [10]
    sidechain HPF 0–300 Hz (the compressor's 4th-order design), [11] link 0–100 %. **Sidechain
    listen** (compressor, expander; multiband bands in S7c): the stage outputs its detector input
    (after the sidechain filter, before any gain) on every lane of the group, through the lookahead
    ring so latency never changes; 5 ms crossfade in and out. It replaces an external sidechain
    input, which is out (see Not planned). Listen is session-only: never encoded, one listener in the
    whole graph (Swift enforces), cleared on profile switch, Stop, output change and Quit; a banner
    names the stage while it runs. Downstream protection still applies. **Delta listen**
    (decision 10) is a second listen mode: dry minus wet before makeup, through the same ring, so
    a listener hears what the stage removes; same session-only and one-listener rules.
14. **Multiband extras (S7c).** The core multiband stage, with per-band auto release, is E6
    S12d's (decision 11); S7c adds to it. Per band: **bypass** (band at unity; with
    `e6.legacy-kernel` on Swift maps it to ratio 1 and makeup 0), **solo** (0/1 band output gain
    ramped over 5 ms; soloed bands sum; session-only), sidechain and delta listen, detector
    choice, and the auto-release toggle in the config; one lookahead for the stage so bands stay
    aligned.
15. **Compatibility.** Every new config field decodes as its default when absent
    (`decodeIfPresent`); defaults are bit-identical to ABI v20 arithmetic, and a short parameter
    count (10 compressor, 6 expander) keeps the old behaviour. One ABI bump per engine slice, taking
    the next numbers after E6 S12. Where the kernel renders (only with `e6.legacy-kernel` on once
    E6 S12 has merged), every extra is disabled with a stated reason (decision 5); multiband
    bypass is the one exception.
16. **Realtime (S6, S7a–S7c).** Document allocation (none on the audio thread; rings sized at
    snapshot build for 10 ms at the stage rate), synchronisation (snapshot and mailbox only),
    latency (0 unless lookahead is on), rates (all eight; times in ms), channels (1–64 lanes,
    linked groups) and reset per `docs/REALTIME_RULES.md`. The engine reads no flag; no ANC or MIMO
    path is touched. realtime-reviewer on every engine slice.
