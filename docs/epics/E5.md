# E5 UI scope clean-up

**Status:** plan approved by owner 18 Oct 2026. S1 merged (#153); S2 revised with the owner 18 Oct 2026 (signal-chain order); S2–S4 to do.

## Goal

The everyday app shows only what a listener needs. Bench and research tools stay in the app
but move out of the main sidebar, and niche restoration processors and lab analysis tools sit
under an Advanced or "More" group. Nothing is removed: every tool stays reachable.

Feature flag: `e5.ui-scope` ("Simplified workspace layout", epic E5), added to `FeatureFlag.all`.
Flag off keeps today's layout exactly. When all three slices have merged and been checked, a
final small PR removes the flag and the old layout.

## What the code looks like today

- Sidebar: `ProductionSection` in `NotchSixty/UI/ProductionRootView.swift:22`, grouped as
  `playback`, `system`, `tools` (Room Advisor, Blind Listening, Acoustic Research, Hardware
  Acceptance) and `extensions`. The sidebar list is at lines 223–258; the detail switch at 292.
- There is no developer menu. The app's only `.commands` replaces the Help group
  (`NotchSixtyApp.swift:2689`). Settings already has a "Developer" card (`NotchSixtyApp.swift:2544`)
  that shows feature flags.
- Dynamics modules (`NotchSixty/UI/ProductionDynamicsView.swift:898`): expander and pause gate
  sit in the Dynamics group; spectral denoiser (its "de-hiss" is a denoiser tuning,
  `DynamicsConfiguration.swift:212`), de-esser and mains hum sit in Restoration, next to
  infrasonic.
- Speaker Measurement Lab (`ProductionSpeakerMeasurementLabWorkspace.swift`) has no tabs; a
  `Mode` picker (line 253) chooses on-axis, off-axis, subwoofer near-field, protected-driver
  near-field and mains/sub timing. Directivity analysis is only reachable from the Room Advisor
  button "Inspect Latest Qualified Lab Directivity" (`ProductionRoomGeometrySection.swift:275`).
  The quasi-anechoic analyser (`SpeakerMeasurementLabQuasiAnechoic.swift`) has no UI at all.
- Navigation is tested in `NotchSixtyTests/ProductionInformationArchitectureTests.swift`
  (no XCUITest target).

### S2 `e5/dynamics-chain-order`: order the dynamics navigator by signal chain

Revised with the owner, 18 Oct 2026. Today's groups do not follow the engine: compression is
listed first but runs late, Restoration straddles EQ, Gain Rider runs in the protection stage, and
the stereo processors run first after room correction. A single Advanced group at the bottom
would break the order further, because its members sit at opposite ends of the chain.

Engine order (`docs/DSP_KERNEL.md`, `N60Dynamics.c`, `N60Protection.c`): Automatic Headroom
(input headroom gain) → DC Offset → Infrasonic → Mains Hum → Spectral Denoiser → *EQ,
convolution, crossover, room correction* → Stereo Mode → Stereo Widener → LUFS Match → Loudness
Compensation → Dialogue Leveler → De-Harsh → De-Esser → Multiband → Compressor → Expander →
Pause Gate → Gain Rider → Soft Clipper → Limiter (Oversampling sets the protection stage's rate).

- [ ] With the flag on, the navigator shows these groups in chain order; niche processors fold
      under a "More" row inside their own group, in their chain position:

      | Group | Shown | Under "More" |
      |---|---|---|
      | Input & Clean-up | Automatic Headroom, Infrasonic, Mains Hum | DC Offset, Spectral Denoiser |
      | Stereo | Stereo Mode, Stereo Widener | |
      | Level & Dialogue | LUFS Match, Loudness Compensation, Dialogue Leveler | |
      | Tone | De-Harsh | De-Esser |
      | Dynamics | Multiband Compressor, Compressor | Expander |
      | Output | Pause Gate, Gain Rider, Soft Clipper, Limiter | Oversampling |

- [ ] No divider in the list. Input & Clean-up carries a small note that it runs before EQ and room
      correction; Stereo carries one that it runs after them.
- [ ] A group whose "More" row is folded shows a badge when any processor under it is on, so active
      processing is never hidden. "More" is collapsed by default.
- [ ] No DSP or snapshot change: grouping and order are presentation only. Flag off keeps today's
      groups.
- [ ] Tests: each module is in exactly one group per flag state; with the flag on, the flattened
      module order equals the engine's stage order above; a module that is on under "More" sets
      its group's badge.
