# E25 Outputs and speaker arrangement, one-DAC support

## Status

- Plan written 1 Nov 2026; owner decisions recorded the same day (fold-down in v1 as S7); plan PR #312.
- Order (owner, 1 Nov 2026): all of E24 (S0–S8) first, then E25, then the original roadmap.

## Goal

Treat the output channels and the speaker arrangement as two separate things. A user whose 5.1
system runs through one two-channel DAC (often into an AV receiver) can set up and use every
feature that two channels physically allow. The UI shows which step is about outputs and which is
about speakers, and states what each configuration can do. When a feature is unavailable, it gives
the physical reason and, where one exists, a fix.

The owner's own system is the acceptance case. A stereo DAC feeds an AV receiver. The sub hangs
off the receiver's pre-out, so the receiver does the bass management and the app sees two channels.

## What exists today

- **Session choice.** `buildTransport` picks a session (`AudioIOEngine.swift:4712–4735`):
  - headphone profile → binaural or stereo;
  - enabled routing → routed N-channel;
  - enabled Output Device Profile → N-channel;
  - otherwise → stereo.
  Quiet Zone runs only on the stereo session (`:1074`, `:1439–1441`). Any configuration that forces
  an N-channel session loses it.
- **The tap.** The process tap is device-scoped (`CoreAudioNChannelTransportSession.swift:434–443`;
  stereo at `CoreAudioError.swift:491`). On a two-channel DAC, 5.x program material arrives already
  folded down by the player or macOS. A wider program needs a program-source device, which today
  only the binaural path has (`HeadphoneDeviceProfileConfiguration.swift:300`,
  `AudioIOEngine.swift:5370`). The C `N60Downmix.h` has no Swift caller, and there is no downmix
  stage in the graph.
- **Mono bass already runs on the stereo session as `STEREO_CROSSOVER` in recombined mode**
  (`core/src/stages_system.cpp:1388`, emitted at `UnifiedGraphConfiguration.swift:274–278`):
  - each lane is high-passed;
  - LP((L+R)/2) × gain × polarity, through an optional phase all-pass, is added back to both lanes;
  - it sits at rank 13, before `ROOM_FIR` (14), so room correction applies full band per channel.
  The gaps:
  - the slope is LR24 or LR48 only (`graph.h:221–226`);
  - the UI never calls this "mono bass";
  - the 2.1 preset with no profile produces it silently (`SystemSetupStartSteps.swift:12–52`).
- **Stereo per-channel controls are user playback controls, not calibration.**
  - What exists: `balance` and a signed `interChannelDelayMs` of ±20 ms
    (`StereoPlaybackControl.swift:969`, `:974`).
  - What is missing: per-channel trim in dB, absolute per-channel delay and per-channel polarity.
  - `UnifiedGraphLane` has `outputGain`, delays and EQ, but it refuses gains ≤ 0, so it cannot
    express polarity (`UnifiedGraphConfiguration.swift:14–20`, `:223–224`). Sub lanes have
    `polarityInverted` (`:79`).
- **Refusals that block a downstream-bass setup.**
  - Routing refuses bass on with no subwoofer source, and the reverse (`AudioIOEngine.swift:4787–4792`).
  - The profile requires a physical sub when bass is on (`OutputDeviceProfileConfiguration.swift:402–416`).
- **Reachability gap.** No production code builds an `OutputDeviceProfileConfiguration`.
  - The wizard Measure step needs one: `MultichannelCalibrationController.swift:265–280` returns no
    sources without it, and the UI says so (`ProductionSystemSetupFlowView.swift:836–839`).
  - The E24 S0 harness hides the gap with `installTwoPointOneProfile()`
    (`NotchSixtyTests/ReferenceRoomTransport.swift:209–223`) on a six-channel device (`:167–169`).
- **Wizard.** `SystemSetupTopology` is stereo, 2.1 or 2.2 (`SystemSetupFlow.swift:23–26`);
  `applyTopology` changes only bass management (`ProductionSystemSetupFlowView.swift:556–560`);
  the session is schema 1 (`SystemSetupFlow.swift:528–571`).
- **Reused types:** `OutputProgramLayout` (`OutputDeviceProfileConfiguration.swift:71`),
  `SemanticSpeakerOutputAssignment` (`:184`), `SpeakerRoutingConfiguration`,
  `AudioOutputDevice.outputChannelCount` (`Devices/AudioOutputDevice.swift:25`), and
  `PlaybackSystemState` with optional additive fields (`ProductProfiles.swift:559–580`).

## Design note

1. **The model is pure Swift, in new files under `NotchSixty/Audio/Arrangement/`.**
   - `SystemOutputs`: device UID, detected channel count, channels in use.
   - `SpeakerArrangement`: `OutputProgramLayout`, 0–8 subs, speakers with roles.
   - `BassHandling`: `.fullRange`, `.dspToSubOutputs`, `.dspMonoToMains` (mono bass on the pair)
     or `.downstream(.receiver | .subCrossover)`.
   - `SpeakerFeedMapping`: each speaker is `.direct(endpoint)` or `.viaDownstream([feeds])`.
   - `SystemArrangement` is stored as an optional additive `PlaybackSystemState.systemArrangement`
     with its own schema 1, following the E8 `speakerRouting` precedent.
2. **One pure compiler.** `SystemArrangementCompiler` derives the existing `bassManagement`,
   `outputDeviceProfile` and `speakerRouting` from the arrangement.
   - The rule: two channels in use always compile to the stereo session, with no profile and no
     routing. Quiet Zone and every stereo-session feature stay available.
   - Only one output per speaker (three or more channels) produces a profile or routing, as today.
   - `.downstream` compiles to bass management off. The refusals above never fire, because no
     sub is mapped.
3. **Capability matrix.** `SystemCapabilityMatrix.evaluate(feature, arrangement, device)`
   returns `.available(note)`, `.limited(note)` or `.unavailable(reason, fix?)`. One table, one row
   per feature; all UI text comes from it, and it feeds E24 S2 `MeasurementReadiness`. Classes:
   - **A**: direct multi-output.
   - **B**: two channels, full range.
   - **C**: two channels, mono bass.
   - **D**: two channels plus downstream bass (a powered sub's crossover, or a receiver at 2.1).
   - **E**: two channels into a receiver driving a 5.x or 7.x arrangement.
4. **Mono-bass engine work (needs-owner).**
   - Give `STEREO_CROSSOVER` an E8-style FilterSpec trailer: LR, Butterworth or Bessel at
     12–48 dB/oct, 40–200 Hz. This bumps the graph ABI to v19.
   - With no trailer, LR24 and LR48 stay bit-identical.
   - Under `e6.legacy-kernel`, new slopes are refused with a reason.
5. **Per-feed calibration.** `SpeakerFeedCalibration` per output: trim ±20 dB, absolute delay
   0–50 ms fractional, and polarity.
   - It is calibration, separate from the user's `balance` and `interChannelDelayMs`.
   - The compiler sums them: lane gain = calibration × balance, and lane delay = calibration plus
     the playback offset.
   - Polarity needs a lane sign. S2 checks first whether the `GAIN` stage accepts −1. If it does,
     the Swift ≤ 0 check is relaxed for an explicit `polarityInverted` lane field; otherwise a
     param is added.
6. **What downstream bass means.**
   - The wizard measures each feed through the receiver as the full system, sub included.
   - Alignment covers L/R feed level, delay and polarity only.
   - Sub alignment, the bass step and the multi-sub optimiser are skipped, with the reason "Your
     receiver sets the subwoofer's level, delay and crossover."
   - Plain-language advice: turn off the receiver's own room EQ to avoid double correction, and
     note that Pure Direct may bypass its bass management.
7. **Wizard (design questions 3 and 4).** The Topology step becomes two steps.
   - **Outputs**: device and channel count, auto-detected and editable down.
   - **Speakers**: layout, sub count and "How is bass handled?".
   - A capability summary card (matrix rows for this arrangement) closes the Speakers step.
   - The flow writes the arrangement, and so the profile, from the UI, which closes the "needs an
     enabled output device profile" gap.
   - Measure sources are the feeds in use, not the speaker roles.
8. **Migration.** Profiles derive an arrangement in memory, deterministically and idempotently:
   - no profile, bass off → 2.0 full range;
   - no profile, bass on → `.dspMonoToMains` (exactly today's recombined sound);
   - enabled profile → direct, with its subs;
   - routing → direct, from the routing speakers.

   The wizard session moves to schema 2:
   - stereo → 2.0;
   - 2.1/2.2 → `.dspToSubOutputs` when the device has enough channels;
   - otherwise → `.dspMonoToMains`, resuming at Speakers with a note.

   With the flag off, the stored field round-trips untouched and nothing reads it.
9. **E24 work that E25 reworks.** E24 is built first. To avoid building twice, E24 slices follow
   these rules:
   - **Topology step, `SystemSetupTopology`, `applyTopology`.** Replaced by E25 S3. E24 makes
     no changes there beyond what a fix needs.
   - **E24 S1 level session.** Lane masks are output-channel indices, chosen in one place (the
     flow model's level-lane function), never derived from the topology. E25 S3 only rewires that
     function.
   - **E24 S2 readiness.** `.blocked` carries open reason and fix values, so matrix reasons slot
     in. E25 S3 deletes the "needs an enabled output device profile" reason.
   - **E24 S3 verify and joint-bass deploy.** Sources come only from
     `MultichannelCalibrationController.sources`, which E25 S3 changes to feeds. Joint bass stays
     class A; the matrix gates it.
   - **E24 S5 shared cards.** Reused unchanged.
   - **E24 S6 acceptance.** The `installTwoPointOneProfile()` shortcut stays and goes into the
     E24 deferral ledger as an E25 S3 item. It is not counted as reachable.
10. **Rates.** The compiler, the matrix and the wizard are rate-free. Crossover, delay and
    polarity tests run at the eight standard rates; delays are specified in milliseconds and
    frames are computed at build time.

## Single-DAC feature audit

What each feature does on a two-channel DAC, for any arrangement. Every gap is an unchecked item
in the slice named in the last column.

| Feature | 2.0 / mono bass (B, C) | Downstream bass or receiver (D, E) | Gap → slice |
| --- | --- | --- | --- |
| Stereo playback, program EQ, dynamics, limiter, protection | Available | Available | None |
| 5.1/7.1 program | Folded upstream by the player or macOS; the tap carries two channels | Same; the receiver may upmix | In-app ITU fold-down from a wider program-source device → S7 |
| Mono bass on the pair | Available (C) | Not offered; the receiver crosses over | Slopes, naming, wizard design → S2, S4 |
| DSP feed to a physical sub | Unavailable: "a subwoofer feed needs a third output" | Unavailable: the receiver feeds the sub | Reason text → S1 |
| Per-feed trim, delay, polarity | Available after S2 | Available on the two feeds | Calibration layer → S2 |
| Sub level, delay, polarity, single or coherent multi-sub alignment | C: crossover phase all-pass only | Unavailable: "your receiver sets them", with advice | Adaptive steps → S4 |
| Multi-sub optimiser, joint bass | Unavailable: needs independent sub outputs | Unavailable, same reason | Reason → S1 |
| Room correction, min or mixed phase | Per feed, full band, after the crossover | Per feed, full system through the receiver | Wizard sources and verify → S3, S4 |

## Feature flag

`e25.outputs-and-speakers` ("Outputs and speaker arrangement", E25), off by default.

- **Off**: the wizard keeps the Topology step and the stored arrangement is ignored.
- **On**: the Outputs and Speakers steps and the capability text appear.

Only Swift reads it; the engine sees only compiled configurations. S2's engine changes are dormant
with the flag off, because no trailer and no polarity are emitted.

## Owner decisions (1 Nov 2026)

1. Fold-down from 5.1/7.1 to two channels is in v1, as the required S7.

Decisions 2–7 are the plan's proposed defaults, approved by the owner as defaults:

2. Mono-bass slopes: `STEREO_CROSSOVER` gets a FilterSpec trailer (ABI v19), with LR,
   Butterworth and Bessel at 12–48 dB/oct.
3. Per-feed calibration (trim, delay, polarity) stays separate from the user's balance and
   inter-channel delay.
4. A downstream 5.x arrangement is recorded for the room advisor and reports, though the app
   cannot control it.
5. Quiet Zone through a receiver is eligible (never live) when the measured latency fits the
   budget; otherwise it is refused with the reason.
6. Bass handling is a manual choice ("How is bass handled?"), with no measurement-based hint
   in v1.
7. One flag for the epic: `e25.outputs-and-speakers`.
