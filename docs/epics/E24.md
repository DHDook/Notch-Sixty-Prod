## Goal

A user on a fresh build can do every room-correction and measurement task from the shipped UI,
through production wiring: play noise and set a level, sweep every seat, align, design bass and
correction (minimum or mixed phase), verify by re-measuring, and save. A disabled measure button
always says why. E10–E12 are ticked done, but several pieces have no production caller; E24
wires them, proves the path end to end with no fakes above the hardware boundary, and proposes
rules so "done" means reachable.

Done when: the S0 harness drives the setup wizard through all ten steps to a passing verification
at all eight standard rates with zero expected-fails, no production service defaults to an
`Unconnected*` stand-in, and the owner's manual smoke checklist (S6) passes on their build.

## Design note

1. **Hardware boundary.** The S0 harness replaces only what touches Core Audio: device lists,
   microphone permission, and the transport factories. `ReferenceRoomTransport` implements the
   same factory signatures by calling the real targeted-bridge process functions block by block
   on a feed through the synthetic reference room (E11 S1, E10 S1 multi-seat). Every Swift
   service above the factories is the production default, built by one
   `SystemSetupServices.production(...)` factory that the app and the harness both call. New
   measurement paths (S1 level session, S3 trial host) take the same seam.
2. **Expected-fail bookkeeping.** Known-broken steps are wrapped in `XCTExpectFailure` (strict)
   with the text `fixed by E24 Sn`. When a slice fixes a step, the strict expectation fails until
   the slice removes it, so a fix cannot land without flipping its marker.
3. **Level session (S1).** A `MeasurementLevelSession` owns the same calibration aggregate and
   targeted-bridge IOProc the sweep uses, in a looping mode: it runs a generator-only core graph
   (the E11 S7 stage, so clamp, 100 ms ramp, ceiling and auto-stop are the core's tested
   behaviour) on the selected output lanes and pushes the microphone channel into an
   `n60_monitor_ring` drained by the existing SPL/RTA worker. The graph and ring are built off the
   realtime thread before start; stop ramps the generator to silence, waits for the ramp-done flag,
   then stops the IOProc. Nothing allocates, locks or logs in the callback. The session ends on
   output change, on the 10-minute auto-stop and on app quit. The Level step always uses this
   session (it needs the meter on the same clock). The Generator card uses the live graph when
   playback runs on the graph renderer (today's `setLiveGenerator` path) and the level session
   otherwise (Q3). Lane selection and the LFE rules of 25 Oct are unchanged; level never exceeds
   −6 dBFS RMS.
4. **Errors.** `engineHookUnavailable` and its blanket message go. Each cause (no output, device
   gone, rate unsupported, permission, session busy, rejected spec) has its own text and, where
   there is one, a fix action.
5. **Readiness (S2).** One pure `MeasurementReadiness.evaluate(...)` returns `.ready` or
   `.blocked(reason, fix)`, from permission, input, output, profile, transport state and
   campaign state. All four measure surfaces read it and show the reason under every disabled
   button. Playback policy (owner, 1 Nov 2026): every measure path stops playback with a visible
   notice, as the wizard does; `playbackMustBeIdle` is no longer a refusal. If Quiet Zone is
   armed, stopping goes through its normal disarm path.
6. **Verify (S3).** `EngineRoomCorrectionTrialHost` applies the candidate through the normal
   snapshot path, keeps the previous configuration for revert, plays the `.sweep` generator on the
   live graph and captures the microphone through the input monitor ring, aligned by the E11 S2
   acoustic timing tier. Verification is the one step that needs the graph renderer running:
   it starts playback on the selected output with other audio muted and restores the prior
   engine state afterwards (Q4). `SystemSetupPostApplyMeasurer` wraps
   `RoomCorrectionDeployController` with that host; both `Unconnected*` classes are deleted.
7. **Gating.** No new flag: E10–E12 ship without flags and these slices repair shipped UI, so a
   flag would keep it broken. Each slice merges complete. Mixed phase stays gated by the existing
   verify path (`canDeploy`, `SystemSetupFlow.swift:205`), never by a flag. Q2 asks whether S1
   should merge dark instead.
8. **Lane-plan install (S3b).** Today one stereo FIR deploys through
   `RoomCorrectionConfiguration.filter` (`AudioIOEngine.swift:670`) →
   `applyRoomCorrectionConfiguration` (:3735) → a convolver slot → `snapshot.roomCorrection` → one
   `N60_STAGE_ROOM_FIR` (`UnifiedGraphTranslator.swift:70–85`). `UnifiedGraphProgramDSP.roomLanes`
   (`UnifiedGraphProgramDSP.swift:97`, applied :290–311, alignment delays :367–372) is set only by
   `RoomCorrectionBassApply.install` (`RoomCorrectionBassApply.swift:167`), which only tests call;
   `makeUnifiedProgramDSP` (`AudioIOEngine.swift:4126–4219`) never sets it. Nothing in production
   calls `RoomCorrectionCore.designGrid` (`RoomCorrectionCore.swift:73`), so no mixed-phase design
   exists, and `SystemSetupBassDesign.optimisation` (`SystemSetupBassCorrect.swift:49`) is dropped
   by `applying(to:)` (:122–140). Decisions:
   - *Stored form.* `RoomCorrectionConfiguration` gains optional `lanes: RoomCorrectionLaneInstall`
     (a rate-independent `RoomCorrectionMultiLaneDesign` plus main-lane delays in seconds). Exactly
     one of `filter` and `lanes` is set, else a validation error. Absent decodes as nil, so saved
     profiles are unchanged. Sub gain, delay and polarity stay in the sub calibration as today.
   - *Wizard designs.* The Correction step designs every kind with `designGrid` per main lane over
     the seat IRs (video mode = minimum phase, music modes = mixed phase) and deploys through
     `lanes` (Q7). The Room Correction workspace's manual FIR deploy stays on `filter`.
   - *Composition.* A pure `RoomCorrectionLaneComposer` merges the room grids with the joint-bass
     grids (`RoomCorrectionBassApply.plan`, :84–137) into one multi-lane design: on a lane that has
     both, the grids multiply on the shared core grid (dB add, phase add); sub lanes carry only the
     bass grid; one latency mode, the room's.
   - *Synthesis off the main actor.* At deploy, `RoomCorrectionRateCache.planAsync` synthesises the
     plan for every nominal rate the selected output exposes before the configuration commits. A
     device or rate change uses the cached plan or awaits a new one before the graph is built. If
     synthesis fails, the session runs with room correction off and Room Correction says why; a plan
     made for another rate is never installed. The engine owns one cache.
   - *Engine.* `LiveGraphInputs` carries the install; `makeUnifiedProgramDSP` sets `roomLanes` and
     `laneDelayFrames` from the cached plan and leaves `snapshot.roomCorrection` empty. Publishing
     uses the existing live-edit path (`transitionDSPGraph`, fade through silence, needed because
     latency changes). No new realtime code: the room FIR and two-band stages (`core/include/n60/graph.h:74`,
     :104) are E10's tested stages, and every buffer is built off the realtime thread.
   - *Legacy kernel* (`e6.legacy-kernel` on): `plan(unifiedGraphEnabled: false)` throws, so the
     wizard falls back to today's FIR path, minimum phase only, and says why.
   - *When mixed phase is offered.* `mixedPhaseAllowed` (`ProductionSystemSetupFlowView.swift:407`)
     becomes: unified graph renderer, music mode, and the plan's `declaredLatencyFrames` within the
     mode's budget (`core/include/n60/correct.h:181–186`) at every exposed rate. Saving still needs a
     passing verification (`SystemSetupFlow.swift:205`; `RoomCorrectionDeployController.swift:61–66`).
   - *Verify.* `verificationCandidate` (`ProductionSystemSetupFlowView.swift:432–455`) takes the
     installed plan's lane-0 stage and latency instead of rebuilding from `filter`. For joint bass,
     `RoomCorrectionPostApplyVerifier.prediction` gains a multi-contribution form that sums the main
     and sub IRs at the main seat, each through its lane stage, delay, gain and polarity. The
     generator already sits ahead of bass management (stage order 3.5 against 13,
     `UnifiedGraphProgramDSP.swift:438`), so a lane-0 sweep reaches the sub with no graph change.
   - *Revert.* `revertCorrection` (:415–425) already restores the whole configuration, which now
     includes `lanes`; bass revert keeps `profileBeforeBass`.
   - Out of S3b: multichannel `deployLatestDesign` keeps refusing under playback (S2 item); the
     S3a finding at 176.4 kHz and above stays an expected-fail.
9. **Repeats, Analysis tab, RTA/SPL (S4).**
   - *Repeats enter the program, not the transport.* `RoomCorrectionSweepProgram`
     (`OutputDeviceCatalog.swift:217`) gains `repeatCount` and `repeatPeriodFrames` (sweep plus tail).
     `sweepSamples` stays "what is played" and becomes a train of N sweeps, each followed by tail
     silence; a new `excitation` field holds one sweep for analysis. Both transports read
     `program.sweepSamples` and play it once (`RoomCorrectionCalibrationTransport.swift:332–338`,
     `MultichannelCalibrationTransport.swift:147`), and pass slicing follows `captureFrameCount`
     (`OutputDeviceCatalog.swift:374–410`), so neither transport changes. `RoomCorrectionSweepSettings`
     gains `repeatCount` (absent decodes as 1). N = 1 is bit-identical to today.
   - *Analyzer* (`RoomCorrectionMeasurementAnalyzer.swift`, before the deconvolve at :165): split
     the observed pass into N period segments; take each arrival from the timing tier (loopback or
     reference channel when present, otherwise a per-segment deconvolve and `directArrivalFrame`);
     call `MeasurementCore.averageRepeats` (`MeasurementCore.swift:191`); deconvolve the average as
     today. With N ≥ 3 and fewer than two accepted, the pass fails with "Too much noise: k of N
     repeats rejected; measure again". Multichannel calibration uses the same program and analyzer
     entry.
   - *Multi-mic* (`MeasurementSeatPlan.swift:132`, `records(from:)`): average each seat's capture
     before `processMultiMic`, with one arrival set for all seats (from the reference chirp, whose
     program repeats with the sweep, else from the main seat), so inter-seat timing survives;
     rejection is per seat. S5 inherits this when it wires `MultiMicMeasurementRunner`.
   - *Verify* (`RoomCorrectionPostApply.swift:150–158`): the generator plays its sweep table once
     (`core/src/stages_generator.cpp:331`), so verify calls `playSweep` min(N, 3) times (no engine
     change), takes each arrival from `impulseResponse`, averages with the period set to the capture
     length, and ignores the drift figure (separate triggers, so the spread is trigger jitter).
   - *Limits.* N ∈ {1, 2, 3, 4, 6, 8} (core maximum 16, `core/include/n60/measure.h:159`).
     `MeasurementReadiness` blocks, with a reason, a timeline whose capture and playback buffers would
     exceed 512 MB (for example 384 kHz, 20 s sweeps, 8 repeats).
   - *Where it shows.* A repeat picker beside sweep length in the shared sweep settings (wizard
     Measure step, Room Correction, multichannel). Each seat or channel result row reads "3 of 4
     repeats kept; repeat 2 rejected (low coherence)" (`RoomCorrectionPositionRow`,
     `ProductionRoomCorrectionWorkspace.swift:1415`; the multichannel measurement row; the wizard
     seat row), plus a drift warning in ppm when `driftWarning` is set. The reason comes from each
     repeat's coherence and level against the core's average defaults. `MeasurementRecord`
     (`MeasurementLibrary.swift:7`) gains optional `repeatCount`, `rejectedRepeats`, `driftPPM`;
     schema stays 1.
   - *Transport change: none*, so S4 stays low-risk. If a builder finds it must edit files under
     `NotchSixty/Audio/CoreAudio/` or `Realtime/` (a frame ceiling, say), the PR becomes needs-owner
     with realtime-reviewer.
   - *Analysis tab.* `SpeakerMeasurementLabTab` (`ProductionSpeakerMeasurementLabWorkspace.swift:2093`)
     gains `.analysis` between Measure and Advanced. `MeasurementAnalysisCard`
     (`MeasurementAnalysisViews.swift:158`: gated IR, waterfall, spectrogram) and the Library view move
     there behind a source picker: latest Speaker Lab capture, latest Room Correction capture, latest
     multichannel capture, or a library record. A `MeasurementAnalysisModel` resolves the source to
     IR, optional raw capture and sweep settings, and computes off the main actor (as the card does
     at :182), cancelling on source change.
   - *Distortion (H2–H5).* Needs the raw capture: rebuild the excitation from the sweep settings,
     deconvolve the full circular response (the stored IR is truncated and loses the negative-time
     harmonics), then `analyzeDistortion` (`MeasurementCore.swift:269`) with `SweepInfo` from the
     sweep. View: fundamental and H2–H5 in dB on a log axis, THD, `noDataDB` hidden, and a note
     naming `minSweepSeconds` when `cleanSeparation` is false. A record without `raw.wav` says
     "Distortion needs the raw capture"; saving a new room capture to the library keeps `raw.wav`.
     The room sweep is a Farina ESS without Novák synchronisation (`OutputDeviceCatalog.swift:279–300`);
     if its H2/H3 differ from the synchronised sweep's by more than 1 dB in the test, S4 switches the
     room program to `MeasurementCore.makeSweep(synchronised: true)` (already used by verify) and
     logs it.
   - *Decay.* `analyzeDecay` (:314) on the IR at one and three bands per octave, 63 Hz–8 kHz; a table
     of EDT, T20, T30 and RT60 with its flags. The Room Correction diagnostics panel keeps its own
     RT60 (:1517); S5's audit decides whether it should read `analyzeDecay`.
   - *RTA/SPL (Q6), recommendation:* move the RTA/SPL card and the Generator out of Advanced into a
     "Level and noise" section on the Measure tab. Since S1 they are the level-setting tools every
     measurement uses. Seat picker and protected-driver commissioning stay under Advanced; Library
     moves to Analysis. The guide (`ProductionUserGuideView.swift:21, 343, 485`) is updated either way.

### S7 `e24/process-safeguards`: rules so "done" means reachable (needs-owner)

Plan only until approved; the PR edits `AGENTS.md` and `.claude/` (slice-builder, plan-tracker,
pr-writer, `/next`). Proposed rules:

1. Two kinds of done: `[x]` only when reachable from the shipped UI through production wiring;
   otherwise `[~]` "built dark" naming the wiring slice.
2. Deferral ledger: any "not wired", "left for" or "follow-up" in a Log becomes an unchecked plan
   item with an owner slice; plan-tracker may not tick a slice with an open ledger entry.
3. Ship gate: a flag-removal or "ship" slice needs an end-to-end test through production wiring
   and zero open ledger entries for its epic.
4. No `Unconnected*` (or equivalent always-unavailable) defaults on injectable services in
   production code.
5. slice-builder and pr-writer trace each feature from the user action to the engine, and every
