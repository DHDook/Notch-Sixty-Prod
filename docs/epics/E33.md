## Design note

1. **Flag.** One flag, `e33.page-enhancements`. Only Swift reads it. Off: today's pages and today's
   published parameters (expander lookahead 0, three multiband bands, input over detector off), so flags-off
   renders bit-identical. Old profiles decode to today's values.
2. **Files shared with E32.** Each slice names the E32 slices it follows. With E33 placed after E32 they are
   met by order; they are stated in case the owner reorders. E33 code never branches on `e32.dynamics-sound`
   once S6 graduates it. E32's owner decisions of 15 Nov 2026 (`docs/epics/E32.md`, decisions 1–5) are in force;
   decision 2 shapes S5a and decision 4 shapes S10.
3. **Subsonic (A1).** Floor 5 Hz for PEQ types (peaking, shelves, high/low pass, notch, all-pass, band-pass)
   in fields, nudges and `EQBandRules`; dynamic bands keep 20–500 Hz. Axis default stays 20 Hz–0.49 fs; a
   range option shows 5 Hz. A band below 20 Hz shows "Subsonic" in its row, and a boost below 20 Hz shows
   the headroom badge's normal rules plus "Boost below 20 Hz raises cone excursion"; there is no boost cap (decision 3).
4. **Import and export on the page (A2).** One Equalizer APO filter-text codec: the importer is extended
   (types LP, HP, BP, NO, AP, LSC/HSC with slope, `Preamp:`), and a writer is added beside it for the page's
   bands. The toolbar's own text import calls the same importer (no second APO parser). Import targets the
   lane being edited, replaces or appends (asked), reports unsupported lines, and is one undo step. E17 S2
   and S8 reuse this codec instead of writing their own (decision 6).
5. **Clipboard (A3).** Private pasteboard type (JSON of band configs) plus a plain-text APO fallback, so
   bands paste into other apps and APO text pastes in. Copy band(s), paste appends, "Copy lane to…" (L↔R,
   Mid↔Side, linked to a lane) replaces the target lane after a confirm. One undo step each.
6. **One preamp (A4).** `EQPreampModel` (State) holds `manualDB`, `autoTrimDB` (auto preamp, E27 decision 5),
   `matchDB` (A/B loudness match, E27 decision 4) and computes `inputPreampDB = clamp(sum)`; it is the only
   writer of `setInputPreampDB` from the page, the controller and `EQComparison`. The page shows each term
   and the total. Profiles store `manualDB` and the auto switch; `matchDB` stays session-only. Old profiles:
   stored preamp becomes `manualDB`. `AudioIOEngine.swift` is not lengthened.
7. **Layout (A5).** Owner design: band list about one third of the width (number, type, frequency, gain,
   status); editor two columns, static (Filter, Frequency, Gain, Q, Slope) left, dynamic right when on.
   Panels size to content; no fixed 250 pt height. Below a breakpoint (builder measures the two-column
   minimum, expected about 900 pt of page width) the editor is one scrolling column. Acceptance: at the
   default window size every control of a fully dynamic band is visible without scrolling (UI test).
8. **Picker (A7).** Sections: Basic (peaking, shelves, pass filters, band-pass, notch), then Special
   (Linkwitz Transform, Tilt, All-Pass, FIR). **Hint (A6):** the allowed frequency and Q range beside the
   Dynamic toggle; when `sanitize` moves a band to fit, an inline note says from and to, until the next edit.
9. **Graph accessibility (A8).** Handles get adjustable actions (frequency by EQNudge steps; a custom
   "Gain" action set via rotor), a visible focus ring, and a one-line hint shown once per install
   ("Scroll for Q, hold Option to listen").
10. **Dynamics chain (B1).** Group headers get numbers from `groups` order ("1 Input & Clean-up" … "6 Output")
    and a thin connector; no processor moves. **Dynamic EQ row (B5):** a non-numbered link row at the EQ
    stage's position in the chain (builder reads the stage order), listing active dynamic bands; it opens the
    Equalizer page with the band selected.
11. **Shared internals (B2a).** Extract the knee law and one-pole gain smoother into a core header only if
    compressor and de-esser output stay bit-identical in every existing test at the eight rates; otherwise
    close with the evidence. The leveler is out (different algorithm). No UI or sound change either way.
12. **Total gain reduction (B2b).** A row on the Dynamics page and Meters > Dynamics showing the per-frame
    sum of the hub's `gr.*` channels of active processors, labelled "Total (sum of stages)"; processors
    without telemetry are listed as not counted. One reader for both pages (C7): both use
    `GainReductionMonitor` over the hub (after E32 S3's monitor changes). The panel bar is the only GR
    readout per processor (B9); the telemetry text drops its GR number.
13. **Ranges (B3).** Sliders keep useful ranges (E28 decision 2); each shows the field's limit when wider
    ("field: 1–100:1"). Multiband core and Swift limits widen to the wideband compressor's (decision 4).
    **Slider (B4):** relative grab (value moves by drag distance from the grab point; a click alone
    changes nothing), commits at most 30 per second while dragging, one final commit on release.
14. **Expander lookahead (B6).** Optional, 0–10 ms (same range rule as the compressor), off by default; the
    detector reads the undelayed signal and the audio is delayed through a ring sized at build, the
    compressor pattern (`ringExchange`). Latency joins `n60_graph_latency_frames`. Ring state carries across
    a rebuild (unlike E28 G46). Builds on E32 decision 2 (E32 S5): the core maps Attack to opening speed and
    Release to closing speed, so a lookahead of at least the Attack time has the expander fully open when the
    first transient after a close arrives. S5a does not branch on `e32.dynamics-sound` (graduated by E32 S6).
15. **Multiband 2–5 bands (B7).** `kMaxBands = 5`, a band-count parameter, per-band arrays at stride 5, the
    allpass-compensated split tree (E28 G42) generalised to N; older 29/43/44-value blocks decode as three
    bands. Splits ascending, at least half an octave apart, 40 Hz to 16 kHz. Defaults: 2 {200}, 3 today's,
    4 {120, 1,000, 5,000}, 5 {80, 400, 2,000, 8,000}. Changing the count keeps retained bands' settings and is
    a rebuild with the normal fade. Lookahead ring scales with bands. Follows E32 S4's crossover crossfade.
16. **Meters (C1–C4, C8, C9).** Zones: tint plus tick shape at −18, −6, −3 dBFS (blue, amber hatched,
    red cross-hatched; checked with deuteranopia and protanopia filters); latched clip is a filled red "CLIP"
    tag with its own reset; no "OK" text. Numeric peak beside each bar. Scale: −60 (default), −96, −120.
    One peak-hold preference (1 s, 2 s default, 5 s, infinite until reset) for Levels and gain reduction.
    One "Reset" menu: clip latches, peak hold, loudness, true-peak max. One `MeterStoppedState` view with a
    Start button on every meter page. Spoken loudness values update at most every 2 s or on a 1 LU change.
17. **Loudness (C5, C6).** Card shows momentary and short-term maxima, a 10-minute short-term history with
    a target line (the Loudness Match target if set, else a chosen −14/−16/−23 LUFS), and "Integrated: last
    24 h". The core value stays as it is (it drives Loudness Match; changing it changes sound) and is labelled
    "Match detector (3 s smoothed)"; only `LoudnessMeter` is called "Short-term" (decision 5). Builds on E32 S3's
    loudness histograms.
18. **New meters (D), where they run.** D1, D2, D3, D5, D6, D7, D8 and the dropout counter are computed in
    `ProductionAnalysisWorker` (off the realtime thread) from the existing capture and hub; no engine change,
    no new demand bit. Each runs only while its card is visible (worker bits, as loudness uses). Definitions:
    - D1 PLR = true-peak max − integrated loudness; PSR = true-peak (last 3 s) − short-term loudness; crest =
      sample peak − RMS over 300 ms. True peak from a BS.1770-4 Annex 2 4x interpolator in the worker.
    - D2 spectrogram: worker FFT frames into a ring image, log frequency, 10 s or 60 s, perceptual colour map.
    - D3 bit activity: per channel, which of 24 fixed-point bits toggle over the window and the effective depth
      ("16-bit content", "scaled, not bit-exact"). The bypass bit-transparent indication is E31's (decision 7).
    - D5 balance: K-weighted short-term L − R in dB. D6: L/R correlation in three bands split at 200 Hz and
      2 kHz (4th-order Linkwitz–Riley), 300 ms window.
    - D7 headroom strip: peak hold at input, post-EQ, post-dynamics (tap 621, while visible) and output in
      one strip; per-stage detail beyond these points is E31's signal-path view (decision 7).
    - Dropout counter (decision 9): a Levels card with dropout events and frames since the session started and
      the time of the last one, from the existing `sessionTransportCounters` underrun and overrun counts (an
      event is a poll in which a count rose); the Reset menu clears it. No engine or Core Audio change.
    - D8 RTA: 31 IEC 61260 third-octave bands, 20 Hz–20 kHz, from FFT bin power; bands under 1 kHz from a
      decimated (to 44.1/48 kHz) second FFT so a 20 Hz band spans at least three bins at every rate.
19. **Input overs (D4)** need exact counts before any DSP, so they live in the core at the graph input
    (`core/src/`), never in `NotchSixty/Audio/Realtime`. A polyphase true-peak detector at the factor of E32
    decision 4 (4x at 44.1/48 kHz, 2x at 88.2/96 kHz, 1x from 176.4 kHz up, the same rule as the protection
    stage; at 1x it counts sample overs, and audio-band content can read up to about 0.56 dB low, so the card
    labels high-rate counts "sample overs") counts samples above 0 dBTP per channel into monotonic
    atomic counters (no read-and-reset, E28 G5). Runs only while Swift publishes `detect = 1` (Levels page
    visible); the card says "since shown". Realtime record: no allocation (state at build), relaxed atomics,
    latency 0 (audio untouched), any rate to 384 kHz, all program input lanes, reset by a generation parameter.
20. **Excluded (owner rule).** K-System scales: a mastering convention with no playback use. D9 SPL and
    noise dose: no dBFS-to-seat mapping exists (the amplifier and DAC volume are unknown), so it is not
    planned in v1; it is deferred to V2 beside V2-11 (decision 8).
