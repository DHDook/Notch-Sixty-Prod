## Goal

Published CPU budgets are met at every standard rate up to 384 kHz on the slowest supported Mac,
with CI benchmarks that fail on regression, through whole-buffer processing, portable SIMD,
faster convolution, multirate low-frequency regions and Audio Workgroup threads; outputs match
today's single-thread full-rate render within stated tolerances.

## What exists today

- **Whole-buffer graph.** `n60_graph_process` (`core/src/graph.cpp:599`) runs each stage over the
  whole block (`runSnapshot`, `core/src/snapshot.cpp:1102`). Inner loops stay per sample in
  places: PEQ section by section (E6 G30), program FIR (`core/src/stages_dsp.cpp:848`).
- **Bridge.** Graph rendered in chunks (`N60RealtimeAudioBridge.c:3073-3099`) inside an outer
  per-frame loop for ring reads, hand-over crossfade and output writes (`:3050`); the per-frame
  kernel call (`:3106`) runs only during hand-over or `e6.legacy-kernel` (E23 deletes it).
- **SIMD:** none in `core/`.
- **FFT:** scalar radix-2 complex float (`core/src/fft.cpp`); E21 S3's vDSP backend is pushed back.
- **Convolution:** non-uniform, segments 256/1024/4096, 256-frame latency
  (`core/src/conv/nufir.hpp:1-21`); E9 left schedule tuning and the worker-thread tail to E20
  (`docs/epics/E9.md:64-71`).
- **Multirate:** only the two-band room and driver FIR (half-band cascade to D = 32,
  `stages_dsp.cpp:853`, `core/src/halfband.hpp`); E6 design note 7's generic region was not built.
- **Precision:** double coefficients, float or double state by stage; E23 S1b and E7 own the
  remaining double-state moves.
- **Denormals:** no FTZ; manual flushes at `stages_dsp.cpp:73-80`, `snapshot.cpp:900-904`,
  `stages_system.cpp:1525`, `:1915`.
- **Threads and checks:** one realtime thread, atomics only (`graph.cpp:77-95`); no Workgroup
  code, RealtimeSanitizer or `[[clang::nonblocking]]`; `test_alloc` covers allocation.
- **CPU budget:** only the rebuild refusal (`cpuBudgetPercent`, `graph.h:631-663`).
- **Benchmarks:** `macos-full.yml:61-107` times the legacy kernel, bridge and `N60Convolution.c`
  (no graph), printed, no thresholds or baselines. The parity suite prints graph ms per second per
  layout and rate (`core/tests/test_parity_suite.c:314`). E9 owes FIR rows with "thresholds set
  in E20" (`docs/epics/E9.md:149`).
- **Build:** `ARCHS = arm64`, macOS 26.0; Xcode Release default optimisation for the core; CI `-O3`.
- **Adaptive SRC:** already Kaiser polyphase, 96 taps (`N60AdaptiveSampleRate.c:222`).
- **UI:** `AudioIOEngine` 27 `@Published`, `RoomTreatmentAdvisorController` 33, about 41
  `ObservableObject` classes.

## Design note

1. **Measure first.** Only S1 has a fixed scope. Each optimisation slice has an entry criterion
   against the S1 table and skips items that miss it, recording the skip in the Log.
2. **Reference machine and metric.** The app is arm64-only, so the slowest supported Mac is an M1.
   Load = render time / buffer period on one core. Reference block 2.67 ms (128 frames at 48 kHz,
   1,024 at 384 kHz); stress block 0.67 ms. Budgets in Q1. CI runners are virtualised M1s, so CI
   gates regressions; the absolute proof is the E22 bench on an M1 MacBook Air.
3. **Benchmark harness.** `core/bench/n60_bench.cpp`, portable C++, built from
   `ci/core_sources.sh` (no E21 dependency). Scenarios: R1 stereo every stage on + 2 subs; R2 5.1
   + 2 subs, room FIR per lane; R3 7.1.4 + 4 subs; R4 262,144-tap FIR on 2 and 8 lanes; R5
   binaural 16 sources, 8,192 taps; R6 wide PEQ at 512 slots (E6 G30); R7 ANC lane feed maths
   offline (compute only, nothing reaches a device). Eight rates, both blocks, median of 5 runs,
   p99.9 and max callback; per-stage ns/sample via compile-time `N60_GRAPH_PROFILE` (compiled out
   of product builds). The harness compares its JSON with `core/bench/baseline-macos-arm64.json`
   and `budgets.json` itself (no Python validator): fail above 1.5x baseline or the budget, warn
   above 1.2x. Baselines change only in a PR that says why.
4. **Floating-point environment.** A scoped flush-to-zero guard inside `n60_graph_process`
   (AArch64 FPCR.FZ, x86 FTZ/DAZ, no-op elsewhere; `core/src/platform/fpenv.hpp`) restores the
   caller's state on return; the bridge callback sets the same. Hot-loop denormal flushes go;
   FINAL_SANITISE stays. No `-ffast-math`.
5. **SIMD layer.** `core/src/simd/simd.hpp`: in-house, over clang/GCC vector extensions (`f32x4`,
   `f64x2`, fma, min/max, select, horizontal sum), plus a scalar build (`N60_SIMD=0`).
   Compile-time selection, no runtime dispatch in v1. Vectorise across lanes first (biquads, same
   operation order per lane), then within a lane where recursion allows. SIMD never lowers a
   stage's state precision (E7, E23 S1b decide it).
6. **Fusion.** Only stage pairs the S1 profile shows as memory-bound are fused; none by default.
7. **FFT and convolution.** Real-input packing and radix-4 SIMD butterflies in the portable FFT;
   a vDSP backend in `core/platform/apple/` behind `fft.hpp` if Q3 says yes (the portable path
   stays the reference). SIMD frequency-domain multiply-accumulate. Schedule re-tuning only where
   R4 or R5 needs it; latency stays 256 frames.
8. **Parallel render (core).** The core owns no threads. The builder splits each snapshot into
   phases at cross-lane stages (matrix, route, bass management, linked dynamics, binaural);
   inside a phase, lane groups are jobs. `n60_graph_process` publishes jobs, runs jobs itself and
   joins before the next phase; host-woken workers call `n60_graph_worker_run`. Jobs are claimed
   by atomic index and write only their own lanes, with fixed summation order, so output is
   bit-identical at any worker count. Unclaimed jobs fall to the IO thread, which spins only on
   claimed ones and counts late joins. The FIR long tail may run as a job one tick ahead, latency
   unchanged. Workers start only when the S1 cost model predicts over 40% single-thread load.
9. **Audio Workgroups (Apple host, Swift/C transport).** Up to three time-constraint worker
   threads join the device's `kAudioDevicePropertyIOThreadOSWorkgroup` (`os_workgroup_join`),
   are woken by a semaphore signal per callback, rejoin on reconfiguration, rate change and
   recovery, and leave on Stop. Swift sets the worker count through the snapshot path.
10. **Multirate regions.** A DECIMATE / INTERPOLATE stage pair with a linear-phase half-band
    cascade (`halfband.hpp`); D per rate keeps the inner rate at least 11.025 kHz (D = 1 at 44.1
    and 48 kHz, 32 at 352.8 and 384 kHz); group delay is stage latency, aligned by the builder;
    added latency capped (Q5). First user: sub lanes after BASS_MGMT. PROTECTION and final stages
    stay full-rate; ANC injection is never decimated in E20.
11. Every new realtime component documents allocation, synchronisation, latency, rate and
    channel assumptions and reset (`AGENTS.md` section 4).

## Feature flag

`e20.parallel-render` (S6: worker threads and Workgroups) and `e20.multirate` (S7, S8: decimated
regions). Both default off until S10, which turns both on before the E22 bench (owner decision 9 Nov 2026), and are removed after the bench. S2–S4 are behaviour-preserving within the stated tolerances, not
user-visible, and ship without a flag, each proven by its parity tests. Only Swift reads the
flags; the core sees a worker count and a region D.
