# E4 Speaker ANC to class-leading

**Status:** plan approved 18 Oct 2026 without S1 (owner: no preview disclaimers while the app is
in development). S2 merged (#157). S3 in review. Software slices S2–S7 run in Phase 1 without the bench; S8–S10
wait for E3 and the bench; S11 waits for E6.

## Goal

Quiet Zone becomes a qualified, honest flagship: the app says plainly what it can and cannot
cancel, cancellation adapts while people move and the room drifts, an instability always ends
in silence rather than a howl, and live ANC is switched on only through one written,
evidence-checked authorisation path.

Feature flag: `e4.adaptive-anc` ("Adaptive Quiet Zone", epic E4), added to `FeatureFlag.all`
with S5. It gates the adaptive controls and the shadow-mode adaptive path in the app shell. The
written criteria (S2) ship without a flag: they change no behaviour.

- Tonal canceller ("predictive canceller" in the plan): `N60ActiveQuietZone.h/.c`, up to 4

- Feed-forward runtime: `N60FeedForwardPreviewFIR`, `N60FeedForwardReferenceBridge`,
  `N60FeedForwardDeadlineBridge` (carries `liveANCQualified`, hard-coded `false` at :321).

## Design decisions

1. **Adapt off the audio thread, filter on it.** The canceller keeps filtering at the native
   device rate (no added delay, which feed-forward cannot afford). Adaptation runs on a worker
   at a decimated rate (the ANC band ends near 500 Hz, so about 2–4 kHz suffices) from
   lock-free rings of reference and error samples, and publishes new weights through a
   preallocated double buffer swapped atomically. CPU cost of adaptation is then the same at
   44.1 kHz and 384 kHz; only the filter itself scales with rate.
2. **Tonal first, then broadband.** Narrowband FxLMS (one complex weight per tone and channel)
   is cheap, robust and fits the existing tone runtime; it ships first. Block frequency-domain
   FxLMS for the broadband feed-forward FIR follows.
3. **Online secondary-path tracking** by the auxiliary-noise method (Eriksson 1989; Kuo and
   Morgan, *Active Noise Control Systems*, 1996, ch. 3): a low-level random probe, inaudible
   under the programme and capped well below the tonal caps, with its own LMS path model. For
   tones, a per-tone complex path estimate is enough. The offline measured path seeds both.
4. **Safety is engine-side and flag-free.** Howl detection and fail-to-mute run in the realtime
   core and are always active whenever ANC output is non-zero, flag or no flag. A trip latches
   mute (10 ms ramp, then hard zero) until the user re-arms it.
5. **One authorisation type.** `LiveANCAuthorisation` is a pure Swift function from evidence to
   a decision with reasons. Every existing `liveANCQualified` reads from it instead of a
   constant. Until the bench evidence exists it returns "not authorised" for every input it can
   receive, so S3 changes no behaviour.
6. **Portable core.** New engine code is C++20 behind a C interface, with no Apple framework;
   decimation and FFT use the existing portable layer (or a small one added here if E21 has not
   landed it yet).

### S2 `e4/qualification-criteria`: write the targets and the authorisation criteria (needs owner)

New `docs/ANC_QUALIFICATION.md`. Proposed numbers below; the owner sets the final values in
review.

- [ ] **Primary seat, tonal:** ≥ 15 dB reduction of each tracked tone, 20–150 Hz, held for
      10 minutes with a person moving within the zone.
- [ ] **Primary seat, broadband feed-forward:** ≥ 6 dB in each third-octave band 31.5–125 Hz
      when the reference leads by at least the measured latency plus 1 ms.
- [ ] **Quiet-zone size:** tonal target minus 5 dB (≥ 10 dB) at six points on a 15 cm-radius
      sphere around the head position.
- [ ] **Other seats:** no third-octave band 20–500 Hz louder by more than 1 dB at any measured
      seat; at the primary seat no band above 150 Hz louder by more than 0.5 dB (waterbed).
- [ ] **Safety:** howl detector trips within 50 ms on an injected instability at every standard
      rate; emergency analog mute verified on the bench; zero trips in a 1-hour soak with music.
- [ ] **Method:** measurement microphone, positions, A→B→A visits (PR99), averaging, the rates
      tested, and how results are published for reviewers.
- [ ] **Authorisation criteria:** the list of evidence `LiveANCAuthorisation` (S3) requires —
      PR97 timing qualified, latency budget met for this interface, PR99 campaign passed against
      the targets above, howl detector qualified, analog mute verified, owner sign-off recorded —
      and that the evidence is bound to one output device UID, interface and rate.
- [ ] Fallback if qualification stalls (open question in the plan): proposed answer, v1 ships
      Quiet Zone as a labelled preview with live output off. Owner decides.

### S4 `e4/howl-detector`: instability detection and fail-to-mute in the engine (needs owner)

- [ ] First C++ engine file: `NotchSixty/Audio/Realtime/n60_anc_guard.{hpp,cpp}` behind a C
      header `N60AncGuard.h`. Per block it checks (a) ANC output energy rising faster than
      6 dB per 20 ms for 3 blocks with no matching rise in the reference, (b) error-microphone
      level above the pre-ANC baseline by 6 dB in any of 16 low-band bins, (c) non-finite or
      clipped ANC output. Any trip ramps ANC output to zero over 10 ms and latches.
- [ ] Allocation-free, lock-free; thresholds from the snapshot; state reset on rate change.
      Documented per AGENTS.md §4.
- [ ] Wired into the tonal and feed-forward ANC outputs in the render kernel, before the
      protection stage. The trip state is published back for the UI ("Quiet Zone muted:
      instability detected. Re-arm").
- [ ] Tests: deterministic C harness plus XCTest at all eight standard rates: injected growing
      loop trips within 50 ms; steady music, programme transients and a stable tone do not trip;
      latch holds until re-arm; mute ramp has no step. Acoustic reference-lab case.
