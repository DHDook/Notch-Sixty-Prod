## Goal

Quiet Zone becomes a qualified, honest flagship: the app says plainly what it can and cannot
cancel, cancellation adapts while people move and the room drifts, an instability always ends
in silence rather than a howl, and live ANC is switched on only through one written,
evidence-checked authorisation path.

Feature flag: `e4.adaptive-anc` ("Adaptive Quiet Zone", epic E4), added to `FeatureFlag.all`
with S5. It gates the adaptive controls and the shadow-mode adaptive path in the app shell. The
written criteria (S2) ship without a flag: they change no behaviour.

## Design decisions

1. **Adapt off the audio thread, filter on it.** The canceller keeps filtering at the native
   device rate (no added delay, which feed-forward cannot afford). Adaptation runs on a worker
   at a decimated rate (the ANC band ends near 500 Hz, so about 2–4 kHz suffices) from
   lock-free rings of reference and error samples, and publishes new weights through a
   preallocated double buffer swapped atomically. CPU cost of adaptation is then the same at
   44.1 kHz and 384 kHz; only the filter itself scales with rate.
2. **Tonal first, then broadband.** Narrowband FxLMS (one complex weight per tone and channel)
   is cheap, robust and fits the existing tone runtime; it ships first. Block frequency-domain
   FxLMS for the broadband feed-forward FIR follows.
3. **Online secondary-path tracking** by the auxiliary-noise method (Eriksson 1989; Kuo and
   Morgan, *Active Noise Control Systems*, 1996, ch. 3): a low-level random probe, inaudible
   under the programme and capped well below the tonal caps, with its own LMS path model. For
   tones, a per-tone complex path estimate is enough. The offline measured path seeds both.
4. **Safety is engine-side and flag-free.** Howl detection and fail-to-mute run in the realtime
   core and are always active whenever ANC output is non-zero, flag or no flag. A trip latches
   mute (10 ms ramp, then hard zero) until the user re-arms it.
5. **One authorisation type.** `LiveANCAuthorisation` is a pure Swift function from evidence to
   a decision with reasons. Every existing `liveANCQualified` reads from it instead of a
   constant. Until the bench evidence exists it returns "not authorised" for every input it can
   receive, so S3 changes no behaviour.
6. **Portable core.** New engine code is C++20 behind a C interface, with no Apple framework;
   decimation and FFT use the existing portable layer (or a small one added here if E21 has not
   landed it yet).

### S6 `e4/adaptive-tonal`: adaptive tonal canceller in shadow mode (needs owner: ANC)

**Approach (approved by the owner 18 Oct 2026).** Facts from the code: the error
microphone reaches only the ambient-monitor HAL input IOProc (`AmbientMonitorTransport.swift`),
not the render thread; the live tonal canceller is stereo (complex L/R weight per tone) and its
weights come from `ActiveQuietZonePlanner.solveStereo` using measured secondary paths evaluated at
each tone.

1. **Shadow never touches the render graph.** The adaptive core runs on the microphone IOProc
   thread (its realtime side) and a Swift-owned worker thread (`Service` every ~4 ms). Its output
   buffer is metered and discarded; nothing connects it to `N60DSPGraphSnapshot`, so it cannot
   play. One function, `AdaptiveQuietZoneOutputPolicy.mayPlay(_:)`, reads `LiveANCAuthorisation`
   and is the only future route to output; in S6 it returns false and nothing calls a play path.
2. **Virtual error.** Because the shadow output is not played, the core adapts on the error the
   microphone would hear if it were: `e_v = e_mic + sum_k Re(S_k W_k exp(j phase))` (the
   adaptive output's predicted arrival through the path estimate), computed on the worker. Core
   change: a `shadow` config flag. With the live tonal canceller running, the shadow weights learn
   the correction on top of it; the UI labels them that way.
3. **Stereo with one error mic.** One complex weight per tone, split L/R by the offline design's
   ratio (fixed per tone); path estimate `S_k = a_k S_L + b_k S_R` from the offline measured paths.
   This keeps the S5 core single-channel and the split identical to today's design.
4. **No probe in shadow** (the probe is output). Path estimates stay at the offline seed; online
   tracking starts with live output (S10).
5. **Howl guard on the shadow stream.** `N60AncGuard` runs on the shadow output with the
   microphone residual, so the UI can report "would have tripped". Real fail-to-mute stays tied
   to live output.
6. **Lifecycle.** The core is created per microphone device and rate; a rate or device change
   destroys and recreates it (clean reset). `MarkDiscontinuity` on IOProc restart or overload.
   Flag off: nothing is created.

- [x] Core: `shadow` mode (virtual error) in `n60_fxlms`, with harness and reference-lab cases.
- [x] `AdaptiveQuietZoneShadow` (Swift): seeds weights and paths from the offline solution, owns
      the worker, feeds the core from the ambient-monitor IOProc, publishes status; flag-gated.
- [x] UI (flag on): per tone, adaptation status, path estimate vs offline seed, predicted vs
      measured reduction at the error microphone, guard state.
- [x] Tests: seeded weights published; shadow output never reaches the render snapshot (flag on,
      authorisation denied); rate change recreates the core cleanly; flag off creates nothing.

Deviation from the plan: microphone frames come from `AmbientCompensationController`'s existing 250 ms poll through a new `microphoneFramesObserver` hook, not from the Core Audio IOProc. This leaves the Core Audio transport untouched, and nothing in shadow is latency-sensitive. Seeds: `ActiveQuietZoneController.adaptiveSeeds`, published from each tonal evaluation. Small measurement noise in a refresh (within 0.5 dB and 5°) keeps the core; a real change rebuilds it. Review fixes: a bounded backlog (8 blocks; drops are counted and marked as a gap), skipped polls marked as gaps, the guard re-armed after any gap, ordered results. ### S9 `e4/adaptive-feedforward`: block FxLMS for the broadband FIR, shadow mode (needs owner)

**Approach (approved by the owner 18 Oct 2026).** What the code has today:
- The block FxLMS core exists (`N60BlockFxlms*` in `N60Fxlms.h`, S5): single channel, ≤ 512
  weight taps, ≤ 128 path taps, not driven by anything.
- The decimator (`N60AncDecimator`, D = floor(fs / 4000), cutoff about 1.2 kHz) already covers
  8–768 kHz.
- The reference microphone has its own one-channel capture (`FeedForwardReferenceTransport` →
  `N60FeedForwardReferenceBridge` SPSC ring), used today only by the PR97/PR98 timing tools.
- The S6 shadow gets only the error microphone, as mono 250 ms polls from the ambient monitor.
- The offline design (`QuietZoneCausalFIRCompiler`) produces 32 left/right taps at the device rate,
  capped at 192 kHz (as is `QuietZoneReferenceLeakageStability`).

1. **Shadow never plays.** As S6: the output is metered and discarded, and
   `AdaptiveQuietZoneOutputPolicy.mayPlay` stays the only route to output (false in S9).
2. **One clock for both microphones.** A broadband filter cannot adapt across two free-running
   clocks, so the shadow needs the reference and error microphones on two channels of the same
   input device. Otherwise it stays off and says why.
   - The reference bridge gains a two-channel mode (reference channel, error channel), filled by
     one IOProc. One-channel callers are unchanged.
3. **Decimated working rate.** Everything adapts at fd ≈ 4 kHz through the existing decimator,
   so the cost is the same at every rate to 384 kHz. Paths get 128 taps (32 ms) and the filter
   up to 512 taps (128 ms). The 31.5–125 Hz target band sits well inside the 1.2 kHz cutoff.
4. **Stereo with one error microphone.** Two block cores, left and right, share one virtual
   error, each with its own path (`S_L`, `S_R`). That is the standard 1 × 2 × 1 multichannel
   FxLMS, with no change to the core's update.
   - New C++ wrapper `n60_ff_shadow` (C interface in `N60Fxlms.h`) holds the two cores, the two
     decimators, the path models and the virtual error.
   - Virtual error: `e_v = e_mic + Ŝ_L * y_L + Ŝ_R * y_R`, the adaptive output's predicted
     arrival.
   - The path model is a bulk delay plus ≤ 128 taps; the bulk delay is added to the wrapper if the
     core's path model lacks one.
5. **Seeds.** The measured secondary paths and the offline complex-frequency design are refitted
   at fd. The causal FIR compiler is run at fd, so the seed follows the offline design exactly,
   not a resampled 32-tap filter.
   - The 192 kHz caps in `QuietZoneCausalFIRCompiler` and `QuietZoneReferenceLeakageStability`
     rise to 768 kHz (rule: every rate to 384 kHz), with tests at the eight standard rates.
6. **Threads.** The capture IOProc only writes the ring. A serial worker, like S6's
   `AdaptiveQuietZoneShadowEngine`, drains the ring and decimates. It then runs the wrapper and the
   howl guard ("would have tripped") and publishes status. No render-thread change.
7. **Comparison with the offline design.** From weight snapshots, in Swift:
   - the predicted reduction per third-octave band, 31.5–125 Hz, for the adaptive weights and the
     offline design;
   - the S2 target (≥ 6 dB) shown against both.
   The UI is flag-gated.
8. **Lifecycle.** The flag is `e4.adaptive-anc` (reused). A device, channel or rate change
   destroys and recreates the shadow. A ring overrun or an IOProc restart marks a gap and
   re-arms the guard.
9. **Known limits.** Programme audio leaking into the reference biases the shadow (S6 has the
   same limit). Echo suppression (`QuietZoneReferenceEchoSuppression`) and online path tracking
   come with live output (S10).
