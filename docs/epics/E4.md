## Goal

Quiet Zone becomes a qualified, honest flagship: the app says plainly what it can and cannot
cancel, cancellation adapts while people move and the room drifts, an instability always ends
in silence rather than a howl, and live ANC is switched on only through one written,
evidence-checked authorisation path.

Feature flag: `e4.engine-lease` (S14, default off); otherwise none since #272. `e4.adaptive-anc` was removed by owner decision (27 Oct 2026);
live output is governed by the per-feature ARM switch (`LiveTreatmentArm`, default off, never
persisted) and the always-on safeguards (`LiveTreatmentSafeguards`). New user-visible work in the
roadmap below that is unfinished still merges dark, behind a new `e4.*` flag where needed.
Planned: `e4.adaptive-tonal-live` (S18, S19; approved, default on once the epic is built out),
`e4.feedforward-live` (S22b, S23, S25), `e4.conversation-unmasking` (S30).

## Design decisions

1. **Adapt off the audio thread, filter on it.** The canceller keeps filtering at the native
   device rate (no added delay, which feed-forward cannot afford). Adaptation runs on a worker
   at a decimated rate (the ANC band ends near 500 Hz, so about 2–4 kHz suffices) from
   lock-free rings of reference and error samples, and publishes new weights through a
   preallocated double buffer swapped atomically. CPU cost of adaptation is then the same at
   44.1 kHz and 384 kHz; only the filter itself scales with rate.
2. **Tonal first, then broadband.** Narrowband FxLMS (one complex weight per tone and channel)
   is cheap, robust and fits the existing tone runtime; it ships first. Block frequency-domain
   FxLMS for the broadband feed-forward FIR follows.
3. **Online secondary-path tracking** by the auxiliary-noise method (Eriksson 1989; Kuo and
   Morgan, *Active Noise Control Systems*, 1996, ch. 3): a low-level random probe, inaudible
   under the programme and capped well below the tonal caps, with its own LMS path model. For
   tones, a per-tone complex path estimate is enough. The offline measured path seeds both.
4. **Safety is engine-side and flag-free.** Howl detection and fail-to-mute run in the realtime
   core and are always active whenever ANC output is non-zero, flag or no flag. A trip latches
   mute (10 ms ramp, then hard zero) until the user re-arms it.
5. **One arm switch, safeguards that cannot be switched off.** (Replaces the evidence-based
   `LiveANCAuthorisation`, owner decision 27 Oct 2026.) Live output runs only while the user has
   armed it, inside limits no setting can disable. From S16 on, safety rests on what the seat
   microphone hears (the "do no harm" verifier), not only on digital level.
6. **Portable core.** New engine code is C++20 behind a C interface, with no Apple framework;
   decimation and FFT use the existing portable layer (or a small one added here if E21 has not
   landed it yet).

### S6 `e4/adaptive-tonal`: adaptive tonal canceller in shadow mode (needs owner: ANC)

**Approach (approved by the owner 18 Oct 2026).** Facts from the code: the error
microphone reaches only the ambient-monitor HAL input IOProc (`AmbientMonitorTransport.swift`),
not the render thread; the live tonal canceller is stereo (complex L/R weight per tone) and its
weights come from `ActiveQuietZonePlanner.solveStereo` using measured secondary paths evaluated at
each tone.

1. **Shadow never touches the render graph.** The adaptive core runs on the microphone IOProc
   thread (its realtime side) and a Swift-owned worker thread (`Service` every ~4 ms). Its output
   buffer is metered and discarded; nothing connects it to `N60DSPGraphSnapshot`, so it cannot
   play. One function, `AdaptiveQuietZoneOutputPolicy.mayPlay(_:)`, reads `LiveANCAuthorisation`
   and is the only future route to output; in S6 it returns false and nothing calls a play path.
2. **Virtual error.** Because the shadow output is not played, the core adapts on the error the
   microphone would hear if it were: `e_v = e_mic + sum_k Re(S_k W_k exp(j phase))` (the
   adaptive output's predicted arrival through the path estimate), computed on the worker. Core
   change: a `shadow` config flag. With the live tonal canceller running, the shadow weights learn
   the correction on top of it; the UI labels them that way.
3. **Stereo with one error mic.** One complex weight per tone, split L/R by the offline design's
   ratio (fixed per tone); path estimate `S_k = a_k S_L + b_k S_R` from the offline measured paths.
   This keeps the S5 core single-channel and the split identical to today's design.
4. **No probe in shadow** (the probe is output). Path estimates stay at the offline seed; online
   tracking starts with live output (S10).
5. **Howl guard on the shadow stream.** `N60AncGuard` runs on the shadow output with the
   microphone residual, so the UI can report "would have tripped". Real fail-to-mute stays tied
   to live output.
6. **Lifecycle.** The core is created per microphone device and rate; a rate or device change
   destroys and recreates it (clean reset). `MarkDiscontinuity` on IOProc restart or overload.
   Flag off: nothing is created.

- [x] Core: `shadow` mode (virtual error) in `n60_fxlms`, with harness and reference-lab cases.
- [x] `AdaptiveQuietZoneShadow` (Swift): seeds weights and paths from the offline solution, owns
      the worker, feeds the core from the ambient-monitor IOProc, publishes status; flag-gated.
- [x] UI (flag on): per tone, adaptation status, path estimate vs offline seed, predicted vs
      measured reduction at the error microphone, guard state.
- [x] Tests: seeded weights published; shadow output never reaches the render snapshot (flag on,
      authorisation denied); rate change recreates the core cleanly; flag off creates nothing.

Built as `AdaptiveQuietZoneShadow` (`NotchSixty/State`) with `AdaptiveQuietZoneShadowEngine` (a serial queue running the core and the howl guard), plus `ProductionAdaptiveQuietZoneCard` (flag-gated). `ProductionRootView` turns it on with the `e4.adaptive-anc` flag. Deviation from the plan: microphone frames come from `AmbientCompensationController`'s existing 250 ms poll through a new `microphoneFramesObserver` hook, not from the Core Audio IOProc. This leaves the Core Audio transport untouched, and nothing in shadow is latency-sensitive. Seeds: `ActiveQuietZoneController.adaptiveSeeds`, published from each tonal evaluation. Small measurement noise in a refresh (within 0.5 dB and 5°) keeps the core; a real change rebuilds it. Review fixes: a bounded backlog (8 blocks; drops are counted and marked as a gap), skipped polls marked as gaps, the guard re-armed after any gap, ordered results. ### S9 `e4/adaptive-feedforward`: block FxLMS for the broadband FIR, shadow mode (needs owner)

**Approach (approved by the owner 18 Oct 2026).** What the code has today:
- The block FxLMS core exists (`N60BlockFxlms*` in `N60Fxlms.h`, S5): single channel, ≤ 512
  weight taps, ≤ 128 path taps, not driven by anything.
- The decimator (`N60AncDecimator`, D = floor(fs / 4000), cutoff about 1.2 kHz) already covers
  8–768 kHz.
- The reference microphone has its own one-channel capture (`FeedForwardReferenceTransport` →
  `N60FeedForwardReferenceBridge` SPSC ring), used today only by the PR97/PR98 timing tools.
- The S6 shadow gets only the error microphone, as mono 250 ms polls from the ambient monitor.
- The offline design (`QuietZoneCausalFIRCompiler`) produces 32 left/right taps at the device rate,
  capped at 192 kHz (as is `QuietZoneReferenceLeakageStability`).

1. **Shadow never plays.** As S6: the output is metered and discarded, and
   `AdaptiveQuietZoneOutputPolicy.mayPlay` stays the only route to output (false in S9).
2. **One clock for both microphones.** A broadband filter cannot adapt across two free-running
   clocks, so the shadow needs the reference and error microphones on two channels of the same
   input device. Otherwise it stays off and says why.
   - The reference bridge gains a two-channel mode (reference channel, error channel), filled by
     one IOProc. One-channel callers are unchanged.
3. **Decimated working rate.** Everything adapts at fd ≈ 4 kHz through the existing decimator,
   so the cost is the same at every rate to 384 kHz. Paths get 128 taps (32 ms) and the filter
   up to 512 taps (128 ms). The 31.5–125 Hz target band sits well inside the 1.2 kHz cutoff.
4. **Stereo with one error microphone.** Two block cores, left and right, share one virtual
   error, each with its own path (`S_L`, `S_R`). That is the standard 1 × 2 × 1 multichannel
   FxLMS, with no change to the core's update.
   - New C++ wrapper `n60_ff_shadow` (C interface in `N60Fxlms.h`) holds the two cores, the two
     decimators, the path models and the virtual error.
   - Virtual error: `e_v = e_mic + Ŝ_L * y_L + Ŝ_R * y_R`, the adaptive output's predicted
     arrival.
   - The path model is a bulk delay plus ≤ 128 taps; the bulk delay is added to the wrapper if the
     core's path model lacks one.
5. **Seeds.** The measured secondary paths and the offline complex-frequency design are refitted
   at fd. The causal FIR compiler is run at fd, so the seed follows the offline design exactly,
   not a resampled 32-tap filter.
   - The 192 kHz caps in `QuietZoneCausalFIRCompiler` and `QuietZoneReferenceLeakageStability`
     rise to 768 kHz (rule: every rate to 384 kHz), with tests at the eight standard rates.
6. **Threads.** The capture IOProc only writes the ring. A serial worker, like S6's
   `AdaptiveQuietZoneShadowEngine`, drains the ring and decimates. It then runs the wrapper and the
   howl guard ("would have tripped") and publishes status. No render-thread change.
7. **Comparison with the offline design.** From weight snapshots, in Swift:
   - the predicted reduction per third-octave band, 31.5–125 Hz, for the adaptive weights and the
     offline design;
   - the S2 target (≥ 6 dB) shown against both.
   The UI is flag-gated.
8. **Lifecycle.** The flag is `e4.adaptive-anc` (reused). A device, channel or rate change
   destroys and recreates the shadow. A ring overrun or an IOProc restart marks a gap and
   re-arms the guard.
9. **Known limits.** Programme audio leaking into the reference biases the shadow (S6 has the
   same limit). Echo suppression (`QuietZoneReferenceEchoSuppression`) and online path tracking
   come with live output (S10).

**Approach (proposed 28 Oct 2026, needs owner approval).** Facts from the code:
- The live tonal canceller plays fixed complex L/R gains per tone. Every change goes through
  `AudioIOEngine.replaceActiveQuietZoneRuntimeTarget` (`AudioIOEngine.swift:1386–1471`), which
  rebuilds and publishes the whole graph. The C runtime crossfades gains linearly over
  `transitionFrames` (`N60ActiveQuietZone.c:147–176`, `:254–300`) and keeps the oscillator phase
  across a same-frequency swap.
- The arm token (`armGeneration`, `AudioIOEngine.swift:1379`) is Swift-only; the C snapshot has none.
- The S15 guard in the kernel (`N60RenderKernel.c:1688–1706`) gets NULL reference and error, so
  only its growth, non-finite and ceiling checks run there.
- The S6 core makes its own tone phase from its frame counter at the microphone rate
  (`n60_fxlms.cpp:248–253`); nothing links it to the phase the kernel plays. Microphone frames
  arrive in 250 ms polls (`AmbientCompensationController.swift:453–476`) without timestamps
  (`AmbientMonitorTransport.readAvailableFrames`, `:148`).
- `AdaptiveQuietZoneOutputPolicy.mayPlay` (`AdaptiveQuietZoneShadow.swift:86–90`) returns
  `arm.isArmed` and has test callers only.
- S12's output-gain rule only disarms (`LiveTreatmentArm.swift:208–211`); nothing re-solves.

1. **Same tones, same runtime, gains through a mailbox.** Arming plays the offline target as
   today (3 s ramp, then the S16 baseline). The adaptive core then refines the gains of those same
   tones, without a graph rebuild. A new kernel mailbox (`N60ActiveQuietZoneGainMailbox`, lock-free
   triple buffer, one writer) carries the arm generation, a sequence number and the complex L/R
   gain per tone. The kernel reads it once per callback in `N60RenderKernelBeginRender` and
   retargets through the existing `schedule_tone` crossfade over 100 ms.
   - It ignores a write whose generation differs from the snapshot's (new `armGeneration` field
     in `N60ActiveQuietZoneSnapshot`, set by `replaceActiveQuietZoneRuntimeTarget`), whose tones
     differ, or that is non-finite. It clamps to the snapshot cap.
   - Disarm clears the target as today and bumps the generation, so a late write cannot play.
2. **Slew limit.** Swift limits each write to ±1.5 dB and ±10° per tone from the gain playing now;
   with the 100 ms crossfade, adaptation stays far below the kernel guard's growth trip
   (6 dB per 20 ms). S15 is unchanged and still runs after the mailbox.
3. **Phase anchor by host time.** Per callback, the kernel writes {host time, rendered frame,
   per-tone phasor, gain playing} into a small SPSC telemetry ring (the realtime bridge passes the
   IOProc `mHostTime` in). The ambient-monitor IOProc records {host time, sample time} per
   callback, and `readAvailableFrames` returns the anchor of the first frame read. The worker maps
   each microphone block onto the phase and gain the kernel played at that instant.
   - This removes the unknown phase offset and the clock drift between the output and microphone
     devices; host time is common to both, and a few µs of jitter is under 0.1° at 150 Hz.
   - Core change: a `remote` mode in `n60_fxlms`, where the worker supplies the demodulation
     phasor and the played gain per block instead of the core's own oscillator. One device or two:
     same code.
4. **Modified FxLMS for the poll delay.** The error lags the gains played by up to one poll
   (250 ms) plus the path. The core adapts on the error re-referenced to its current weight,
   `e_v = e_mic − Re(Ŝ G_played e^{jφ}) + Re(Ŝ W e^{jφ})` (Bjarnason, 1992). This is S6's virtual
   error with the played term subtracted, and it keeps the delay out of the loop's stability while
   Ŝ is accurate. Live `convergenceSeconds` defaults to 1 s.
5. **Online path tracking per tone, by a gain dither.** Decision 3's broadband probe would have to
   be played by the kernel and captured sample-aligned on another device, which waits for S23.
   For tones, each output gain carries a small pseudo-random complex dither (±0.5 dB, ±3°, a new
   value every 0.5 s from a seeded sequence the worker knows). The worker estimates
   `Ŝ_k = Δm_k / ΔG_k` by LMS on the demodulated tone. This is the per-tone form of the
   auxiliary-noise method: the probe sits at the tone frequency, below the anti-noise, and needs no
   broadband alignment. Seed: the offline path (`ActiveQuietZoneController.swift:1294–1299`).
   Programme content at a tone frequency slows tracking until S22. Approved by the owner
   (28 Oct 2026). Follow-up after S23 lands (sample-aligned capture across devices): add decision
   3's broadband probe as an optional improvement beside the dither.
6. **Mic moved: supervised re-solve** (owner decision, 28 Oct 2026). Compared with the path
   captured at arming, per tone: up to 30° and 3 dB is tracked (temperature, small head moves; the
   core is stable to 60°, S5). Beyond 30° or 3 dB on any tone for 1 s, or 15° within 2 s on two or
   more tones (too fast for temperature), the controller starts a re-solve for the new position. A
   pure, deterministic state machine (`MicrophoneMoveResolver`, Swift) drives it each poll:
   1. **Reduce.** Gains drop 10 dB over 250 ms. The attempt cap is 10 dB below the cap held
      before the move, and never above it. The mailbox record carries this cap and the kernel
      applies the lower of it and the snapshot cap.
   2. **Re-identify** for up to 3 s. The path LMS restarts from the tracked estimate with a faster
      step and the dither raised to ±1.5 dB, ±9°.
   3. **Re-baseline.** The anti-noise ramps out over 1 s, S16 captures a new ANC-off baseline over
      2 s at the new position, and then ramps back in over 3 s. Weights are re-seeded as
      `W · Ŝ_old / Ŝ_new`, so the predicted anti-noise at the microphone is unchanged.
   4. **Supervised adaptation** for up to 10 s, at the attempt cap.

   While the re-solve runs, S15 (kernel and worker guards), the lease, the generation check and S16
   all stay active. Thresholds are tighter than S16's. Any of these disarms with reason
   `microphoneMoved`, and the S17 recorder logs which one fired:
   - before the new baseline: any tone or band more than 1 dB above the arming baseline for 1 s;
   - after it: any tone or band more than 0.5 dB above the new baseline for 1 s;
   - the anti-noise rises more than 3 dB within 1 s without at least 1 dB less at the seat, or sits
     at the attempt cap for 1 s without the tone dropping by 3 dB;
   - the path has not converged in 3 s (two successive estimates more than 10° apart), or it is
     still moving faster than 5° per second;
   - 20 s pass from the trigger without success;
   - a second move within 60 s of a success, or a fourth re-solve in one arm.
   A guard trip disarms with `instabilityTrip` as usual.

   **Success:** within the 20 s, every tone is at least 3 dB below the new baseline and nothing is
   worse than it. Then:
   - the new path becomes the reference for the next mic-moved check;
   - the new baseline becomes S16's;
   - the cap returns to its pre-move level in 3 dB steps every 5 s (S20 takes this over);
   - the recorder and the UI say "re-solved after the microphone moved".

   Silence is guaranteed: every failure goes through the normal disarm (1 s ramp to silence), and
   the kernel checks in 1 stand alone. A non-finite path, a model reset or more than two gaps in
   10 s disarms with a new reason `adaptiveFault`.
7. **Gate (replaces `mayPlay`).** `AdaptiveTonalOutputGate.evaluate(_:)` (pure, MainActor) is open
   only when all hold: flag on; Quiet Zone armed with the generation the kernel holds; the target
   has ramped in; S16 has a baseline and reads `ok` (a `warning` freezes the gain); no S15 trip
   since arming; lease renewed (when `e4.engine-lease` is on); path within tolerance or a re-solve running; core adapting
   with no fault. The controller evaluates it each poll and hands an atomic {open, generation} to
   the shadow engine, which writes the mailbox only while open. Closing it stops writes and holds
   the last gain; any disarm ramps out as today. The kernel checks in 1 stand alone, so a gate bug
   cannot play stale or unbounded gain.
8. **Closed-loop guard in the worker.** The kernel guard cannot see the microphone. The worker
   runs `N60AncGuard` on the reconstructed output with the microphone residual as error (the S6

#### S20 `e4/earned-cap`: commissioning ramp by earned trust (needs owner: protection)
- [x] The cap starts at −40 dBFS and rises in 3 dB steps, never past −18 dBFS, only after S16 shows
      stable improvement for a set time. Earned levels are stored per binding (output, input,
      rate, output gain) and drop back to −40 dBFS on any binding change.

**Approach (proposed 30 Oct 2026, needs owner: protection, engine).** Facts from the code:
- The cap is a constant today: `LiveTreatmentSafeguards.defaultPeakCapDBFS = −40`, hard maximum
  −18 (`LiveTreatmentSafeguards.swift:14–18`, clamp `:44–59`). The controller passes no cap to
  `limitedInjectionPeak` (`ActiveQuietZoneController.swift:713–722`), and the engine always writes
  −40 into the snapshot (`AudioIOEngine.swift:4508–4515`).
- The kernel limit is the lower of −18, the snapshot cap and the record's attempt cap
  (`N60ActiveQuietZone.c:608–617`); a mailbox record can only lower it.
- Defect: `ApplyMailbox` lowers `runtime->peakCapLinear` to the attempt cap (`:665–666`) and only
  `Schedule` raises it again (`:226–229`). After an S18b re-solve the per-sample clamp stays 10 dB
  down until the next graph publish, whatever the step-back writes. S20 fixes this.
- S18b's step-back sits in the coordinator: `capInForce` is fixed at arm from
  `plannedPeakLinear`, and steps of 3 dB every 5 s come back up to it
  (`AdaptiveTonalLiveCoordinator.swift:101–102`, `:217–220`, `:276–289`).
- The binding is already `LiveTreatmentEnvironment` (`LiveTreatmentArm.swift:87–104`). S12
  disarms on any change in it (`:198–217`; gain tolerance 1 dB). The pattern for a persisted
  per-device store is `QuietZoneMeasuredLatencyStore` (`QuietZoneMeasuredLatency.swift:6–40`).

Design:
1. **Where the cap lives.** A pure Swift `EarnedCapPolicy` (State/, MainActor, deterministic,
   injected clock) owns the cap in force: there is one cap and one owner. The controller steps it
   once per poll and passes `capDBFS:` to `limitedInjectionPeak`. The result reaches
   `plannedPeakLinear` and the coordinator, which writes it as the mailbox `attemptCapLinear`
   (S18a record, no format change). The S20 policy replaces the coordinator's
   `capInForce`/`capSteppingBackSince` logic.
2. **Kernel (defence in depth).** With the flag on, the snapshot carries `peakCapLinear` = −18
   (the arm's ceiling) and a new `initialCapLinear` = the earned level at arm. The runtime keeps a
   `ceilingLinear`. It starts at `initialCapLinear`, and a record asking for more raises it by at
   most 3 dB per 5 s of rendered frames (`round(5 · fs)`, so it holds at every rate). Lower
   requests apply at once. The per-sample clamp uses `min(ceiling, record cap)` on every apply,
   which fixes the defect above. A Swift bug that asks for −18 at once gets one step per 5 s,
   never past −18. Realtime: no allocation, one compare and one frame counter per callback;
   `Reset` and disarm (generation bump) return the ceiling to `initialCapLinear`.
3. **Stable improvement.** A poll counts towards the next step only when all of these hold:
   - the S18 gate is open and adapting, with no re-solve running;
   - the S16 verdict is `.ok`;
   - `Measurement.minimumToneReductionDB` ≥ 3 dB and `worstIncreaseDB` ≤ 0.5 dB
     (`DoNoHarmVerifier.swift:141–147`);
   - there has been no S15 or worker guard trip and no S21 thermal hold;
   - the anti-noise is cap-limited: the peak played over the poll is within 1 dB of the cap
     (S18 telemetry). If the cap is not what limits the reduction, the cap does not rise.

   **Set time:** 60 s of consecutive qualifying polls. Each step adds 3 dB and restarts the timer
   (−40, −37, … −19, then −18), so about 8 minutes from the first arm to the top. Any polls that
   do not qualify restart the timer. A `warning` also holds the level.
4. **Per-binding storage.** `EarnedCapBinding` holds the output UID, input UID and nominal rate
   (integer Hz) as the key. The value is `{earnedDBFS, outputGainDB, earnedAt}`.
   - It is stored in a new `EarnedCapStore`: UserDefaults, JSON under a new `PreferenceKeys`
     entry, at most 32 records, least recently used dropped. It is written on the MainActor at
     each earned step and never touched by the realtime path.
   - Lookup at arm: the key must match exactly and the stored gain must be within 1 dB of the
     current gain (the S12 tolerance). Anything else starts at −40, and the next earned step
     replaces that key's record.
5. **Binding change.** Any change S12 sees, while armed or between arms, makes the cap in force
   −40 within one poll, before any disarm or future re-solve completes. The new binding earns
   from −40 unless it has a matching record. Effect on the stored record:
   - `seatRegression` or a guard trip resets that binding's record to −40;
   - `adaptiveFault` or a failed `microphoneMoved` drops it one step;
   - a user disarm, lease expiry, Quit or teardown keeps it.
6. **Mic-moved hook (takes over S18b 6).**
   - `.reduceGains` freezes the earned timer and records `preMoveDBFS`. The attempt cap is
     `preMove − 10 dB`, then the 3 s ramp-in as S18b does now.
   - `.succeeded` steps the cap up 3 dB every 5 s to `preMoveDBFS` and never beyond it. The
     kernel ceiling already sits at the pre-move level, so these steps are not throttled.
   - Back at `preMoveDBFS`, the 60 s timer restarts from zero.
   - A failure disarms as S18b does and applies rule 5.
7. **Interfaces.** The per-tone cap in force is `min(earned, planner headroom, S21 curve at f,
   attempt cap)`, and every limit lowers only. A new `SafetyEventKind.cap` logs each step, reset
   and resume. The Quiet Zone status shows "Anti-noise limit −31 dBFS (earned)".

Flag: `e4.earned-cap` (new, default off, needs `e4.adaptive-tonal-live`). Off: the cap is
−40 dBFS as today, no store reads or writes, and the snapshot is bit-identical. One PR,
about 900–1,200 lines, needs-owner (protection, engine).

Tests (no live ANC; fake session, twin and harness only):
