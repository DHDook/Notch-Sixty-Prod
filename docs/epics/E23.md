#### S4 part 4 plan

The count is 63 stored `var`s, not about 40: 34 were `private(set)` (read by the UI, written only in the class) and 29 were `private` (82cef68, e6308f7). Swift has no "this type's files only" access, so an extension in another file can write a property only if every file in the module can. Two remedies, chosen per group:

- **State box:** a `@MainActor final class` in its own file (`@Observable` where the UI reads it, `@ObservationIgnored` fields otherwise), held by the engine as `let`. Its fields are `private(set)` in the box file and change only through intent-named methods that keep the group's invariant. Read-forwarders for the old names (`var recoveryAttempts: UInt64 { recovery.attempts }`) live in an extension in the box file, so callers and the UI do not change. Used where one extension writes a coherent group.
- **Mutator next to the stored state:** the property goes back to `private(set)` in `AudioIOEngine.swift`, with one internal method beside it that stores and publishes together (`commitEQConfiguration(_:)` stores, then republishes), so no writer can store without publishing. Used for single values the UI reads and one setter extension writes.

**Design note.**

1. **What "delete the kernel" means.** `N60RenderKernel.{c,h}` (2,918 + 662 lines) holds two things. The render kernel (create, process, diagnostics) is deleted. The configuration snapshot `N60DSPGraphSnapshot` and its 23 setters (`N60RenderKernel.c`:997–1406) is still how Swift builds a configuration: the translator reads it (`UnifiedGraphTranslator.swift`:17, :32, :298) and `N60UnifiedGraphEligibility.h` reads it. The same split applies to `N60Dynamics.{c,h}`: the `N60DynamicsSnapshot` setters (:532–1460) stay, and the processing (:1637 onward) goes. K2 moves the snapshot types, setters and limits (`N60_MAX_EQ_*`) without changes into `NotchSixty/Audio/UnifiedGraph/N60StereoConfigSnapshot.{h,c}` and `N60DynamicsConfigSnapshot.{h,c}`. This is existing C moving out of `Realtime/`, not new engine code (Q1). E21 S12 ports them to C++ in `core/`; they are never replaced with Swift types (owner rule, 25 Nov 2026: engine C is ported to C++, never replaced with Swift). `N60RenderKernelDiagnostics` is the bridge's stereo readback, so it is renamed `N60StereoBridgeDiagnostics`, not deleted.
2. **No fallback after K1.** Today 40-odd `UnifiedGraphFallbackReason` cases (`UnifiedGraphTranslator.swift`:1165) and the N-channel "legacy render core kept" path (`CoreAudioNChannelTransportSession.swift`:407, :715) fall back silently. After K1, a configuration the graph refuses, or a graph that fails to build, fails the start with the named reason and the `Failed` state, shown by the existing error surface. It never falls back to the kernel and never sends unprocessed audio (Q2). N-channel sessions with an Audio Unit rack are not required to run on the graph today (`+Transport`:349–350), so K1 must prove they do.
3. **Three approaches for each test.** *Graph-only*: the assertion is already analytic (an EQ gain, an exact delay, a null, bit transparency), so the same assertion renders through `UnifiedGraphHost.processOffline` (or `n60_graph_process` in C) from the same snapshot. *Frozen corpus*: the kernel is the only independent reference (multi-stage parity), so the graph's output is captured once, in the same run that asserts parity with the kernel at today's tolerances, and checked in. *Retire*: the test's subject is the kernel's own API (render context, publish contract, kernel against kernel). It is deleted, and the PR names the graph test that covers the behaviour, or ports the missing assertion.
4. **Frozen corpus format.** For each case and rate: latency in frames, 64 block RMS values (dB, double), the peak, and the first 256 samples after the latency. The Swift corpus is JSON in `NotchSixtyTests/Fixtures/E23Corpus/` and the C corpus is `core/tests/e23_corpus_*.inc`, under 500 KB in total. A test compares within 0.01 dB block RMS and 1e-5 absolute per sample (Q3). That allows SIMD and summation-order changes and catches any real DSP change. It is written only by a Debug run with `N60_E23_WRITE_CORPUS=1`. After K2 it can no longer be regenerated against the kernel, so a regeneration is a deliberate DSP change with a cited reason. The five C parity tests then stop including `NotchSixty/` sources and run on Linux CI as well.
5. **G8.** The loudness and multiband parity tests compare against the float kernel (`core/tests/test_loudness_parity.c`:86, `test_multiband_parity.c`:80, `UnifiedGraphMultibandTests.swift`:128). K2 deletes that reference, so K2 rewrites them against a double-precision reference built in the test and restores the targets the files were written for at every rate: -120 dBFS peak, -130 dBFS RMS, telemetry within 0.01 dB, and multiband gain reduction within 0.01 dB (Q3).
