## Goal

The Equalizer page matches the best EQ editors (FabFilter Pro-Q, REW, EasyEffects) on feel,
on showing what each filter does, and on safety: undo, precise entry, fine and keyboard
control, phase and impulse views at every rate up to 384 kHz, a headroom read-out, an EQ-level
A/B, band listening and click-free bypass.

## Design note

1. **Testable cores, thin views.** Plain-Swift types with XCTests: `EQValueParser`, `EQNudge`,
   `EQEditHistory`, `EQGraphGeometry`, `EQFilterAnalysis`, `EQHeadroomPredictor`,
   `EQComparisonSlots`. Views only bind them.
2. **Parsing.** Frequency: `2k`, `2kHz`, `250hz`, `1.5 kHz`, `1,5k` (locale separator and `.`).
   Gain: `+3`, `-3 dB`, `3db`. Q: a number or octaves (`1 oct`; Q = √2ᴺ / (2ᴺ − 1)). Out of range
   clamps to the band type's range; unparseable text is rejected and the old value kept.
3. **Steps** (field arrows and graph keys share them). Frequency ×2^(1/12), Shift ×2^(1/3), Option
   ×2^(1/96); gain 0.5, 3, 0.1 dB; Q ×1.1, ×1.5, ×1.02. Graph: Left/Right frequency, Up/Down gain,
   Delete removes, only while the graph has focus (`.focusable()`, `onKeyPress`).
4. **Gestures.** Hover (`onContinuousHover`): crosshair, cursor frequency and curve dB; over a
   handle, band number, type, frequency, gain, Q. Scroll (an `NSViewRepresentable` catcher; SwiftUI
   has no scroll-wheel event on macOS) or pinch over a handle scales Q (×1.05 per notch); no-op
   without Q. Double-click empty graph adds a peaking band there (Q 1.0; message at the band
   limit); double-click a handle resets gain to 0 dB and Q to the type default. Shift-drag locks
   the dominant axis after 4 pt; Option-drag moves at 0.1×. Selection is on mouse-down, so the
   double-click recogniser adds no delay.
5. **Undo.** `EQEditHistory` registers (before, after) states with the window `UndoManager` (tests
   inject one). Undo applies `before` via `replaceStereoEQConfiguration` only if the live state
   equals `after`; otherwise the history clears (an outside writer changed the EQ). A drag is one
   step. Covered: move, add, remove, enable, type, frequency, gain, Q, slope, constant-Q, Linkwitz
   target, dynamic settings, channel mode, phase mode, page imports. Not covered: bypass, the
   edit-lane picker, A/B, audition. Depth 100.
6. **Same math as the engine.** Minimum and mixed phase read the compiled sections from
   `StereoEQConfiguration.makeGraphSnapshot`; linear phase calls `N60LinearPhaseEQDesign` with
   `linearPhaseBands`. Phase from each section's H(e^jω), unwrapped; group delay closed form
   τ(ω) = Re[Σ k cₖ e^(−jωk) / Σ cₖ e^(−jωk)] (numerator minus denominator); linear phase shows its
   constant (N − 1)/2 delay and the residual phase. Impulse: the cascade on a unit impulse in
   double precision, or the FIR taps; step is the running sum. Long work runs off the main thread
   on value types, cancelled by the next edit, 50 ms debounce.
7. **Ranges.** x runs 20 Hz to 0.49·fs (188.2 kHz at 384 kHz), with an Audible (20 Hz–20 kHz) zoom.
   y presets ±3, ±6, ±12, ±24, ±36 dB and Auto (largest |response| + 3 dB, next preset; only grows
   during a drag). Drags map to the visible range; fields keep ±24 dB. Choices persist via
   `PreferenceKeys`.
8. **Curves.** Selected-band fill to 0 dB; "Band curves" Off / Selected (default) / All; dynamic
   bands shade their gain range; the other lane in Independent and Mid/Side is a dashed ghost.
9. **Headroom (S3a).** Steady-state worst-case sine gain per output over a 1/48-octave grid plus
   band centres: |H| for L/R; (|H_M + H_S| + |H_M − H_S|) / 2 for Mid/Side; dynamic bands at their
   upward limit. Badge: green when preamp plus headroom attenuation covers it, amber when not, red
   when the post-EQ meter's `overRangeSamples` rose or peak hit −0.1 dBFS in the last 2 s. It says
   it is a sine prediction, not an inter-sample bound. No new engine tap.
10. **Auto preamp (S3a).** Peak-based: preamp = user trim − max(0, predicted boost), rounded up to
    0.1 dB, published with `setInputPreampDB` on commit and with the drag's coalesced publish. The
    slider then edits the trim. Toggle and trim persist in the profile (new fields, default off
    and 0). Preamp and output gain also appear on the page, bound to the existing setters.
11. **EQ A/B (S3b).** Slots A and B (bypass excluded), copy either way, toggle, Keep A / Keep B,
    an undo history per slot. The toggle publishes the other slot via
    `replaceStereoEQConfiguration` (coefficient crossfade or 20 ms rebuild fade). Linear phase
    prepares both FIR programs ahead (3 slots, `N60Convolution.h:87`) so the toggle swaps slots.
    Optional loudness match: 10·log₁₀ of the K-weighted (ITU-R BS.1770-4) pink-noise power ratio,
    as a preamp trim on the louder slot. The profile saves the active slot; B is session-only.
    Mutually exclusive with content A/B.
12. **Audition (S3b).** "Listen" (button, or Option-click-hold a handle) replaces the EQ while held
    with one unity-peak band-pass at the band's frequency and Q (corner and Q 0.707 for shelves and
    HP/LP), so level cannot rise. It is an `EQAuditionOverride` input to `makeGraphSnapshot`, never
    written to `stereoEQConfiguration`, the profile or undo, and ends on release, page leave,
    window close, transport stop or after 30 s. Minimum phase only (question 3).
13. **Bypass (S3b).** Test first; change the engine only if the default path fails. Criterion: a
    −6 dBFS 1 kHz sine through +12 dB of EQ, bypass toggled mid-block: no sample step above the
    sine's largest step + 1e-4, done within 25 ms, level never above max(before, after) + 0.5 dB
    (equal-power fades of correlated signals swell up to 3 dB; the fix would be a linear wet/dry
    ramp on the EQ stages, with realtime-reviewer).
14. **Realtime.** S3 engine changes document allocation (none on the audio thread), synchronisation
    (snapshot publish only), latency (unchanged), sample rates (all eight; ramps in ms), channels
    (stereo and every N-channel program lane the EQ runs on) and reset, per
    `docs/REALTIME_RULES.md`. No ANC or MIMO path is touched; the engine reads no flag.

## Feature flag

`e27.eq-safety` ("EQ safety and compare", E27), off by default, added in S3a. It gates auto preamp,
EQ A/B and audition: they change what the engine plays or the gain it publishes, land over two
PRs, and the owner should hear them first. Only Swift reads it. Off: the page is as after S2.

Flagless: S1 and S2 are interaction and drawing on existing bindings, complete when merged, and
change nothing the engine renders. The headroom badge reads existing meters and the page gain
controls reuse existing setters. A bypass fix, if needed, is a click fix proved by its test.

## Open questions for the owner

1. **Undo scope.** Recommend covering dynamic settings, channel mode and phase mode, not bypass,
   A/B or audition (design 5).
2. **Outside edits.** Recommend clearing the history when the EQ changes outside the page (profile
   switch, Room Correction apply) rather than undoing that change.
3. **Audition.** Recommend a held band-pass "Listen", minimum phase only. Alternative: "Solo" (only
   this band's effect), which in linear phase needs a FIR redesign per press. Which, or both?
4. **A/B loudness match.** Recommend a predicted K-weighted pink-noise match (instant, no capture)
   rather than the captured-LUFS `ContentABLoudnessMatchPlan`.
5. **Gain compensation.** Recommend peak-based auto preamp (prevents clipping) only; a
   loudness-preserving mode keeps perceived level but can clip.
6. **Legacy kernel bypass.** It steps hard into bypass. Recommend leaving the frozen fallback alone
   (E23 deletes it).
7. **Order.** Recommend running E27 next, after #395 merges, before the remaining E9 work.
