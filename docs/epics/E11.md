# E11 Measurement suite

**Status:** Merged: S1–S9b (#210–#221). S10 `e11/overlays-and-ship` is in this PR (needs-owner): flag `e11.measurement-suite` removed, suite always on, E11 software-complete pending bench. Next: E22 bench checks (deferred, no hardware now); then E10. Open owner decision: none.

## Goal

A measurement suite that buyers can compare with REW: repeat-sweep averaging with a timing
reference that survives separate-clock USB microphones, RTA and SPL meter, signal generator,
waterfall and spectrogram, H2–H5 distortion, RT60/EDT, multi-microphone capture, a measurement
library with overlays and A/B, a gated speaker view, and REW/FRD/ZMA import and export, at every rate from 44.1 to
384 kHz. Software is done when every slice passes its reference-lab tests; the REW match within
0.5 dB on the same captures (gate G3) is checked on the bench in E22, since no REW is available now.
E10 builds on S1, S2 and S5.

## Design note

1. **Where the maths lives.** New analysis code is C++20 in `libn60core`, under `core/src/measure/`,
   behind its own C header `core/include/n60/measure.h` with `N60_MEASURE_ABI_VERSION 1`
   (separate from the graph ABI so analysis changes never bump the realtime interface). This is
   E21's first "move the maths" item (owner, 24 Oct 2026). Analysis runs off the audio thread only: it may allocate,
   never throws across the C boundary, and is deterministic (fixed summation order, no threads,
   seeded noise). Swift wraps it in `MeasurementCore.swift`. The Swift analyser stays for flag
   off and is deleted with the flag.
2. **Offline FFT.** Add `n60::fft::offline`: real-input, double precision, power of two up to 2²⁴
   (a 30 s sweep plus tail at 384 kHz), portable implementation in core. The realtime FFT is
   untouched. Budget: a 2²² transform under 1 s in Release on the dev Mac; if missed, a vDSP
   backend goes in through the same interface (E20/E21).
3. **Sweep and deconvolution.** New sweeps under the flag are synchronised ESS by default
   (owner, 24 Oct 2026; Novak et al., 2015) so harmonic impulses land at exact, phase-coherent offsets −T·ln k / ln(f2/f1).
   Deconvolution keeps today's regularised division (parity with the Swift analyser on identical
   input) but returns the full circular response, so negative time is available for H2–H5.
4. **Timing.** Three tiers, chosen automatically and recorded on each measurement:
   (a) electrical loopback channel on the mic's interface (exact); (b) acoustic timing reference:
   a 0.25 s log chirp from 2 kHz to min(20 kHz, 0.45·fs) on a user-chosen reference speaker,
   played 0.3 s before every sweep in the same pass, whose arrival defines t = 0; (c) none, direct
   arrival as today. Inter-channel delays are reported only for (a) or (b). A reference whose
   correlation peak is under 20 dB above its neighbourhood fails the measurement with a clear
   reason, never a silent fallback.
5. **Averaging.** 1–16 repeats, default 2 (owner, 24 Oct 2026). Repeats are aligned by
   sub-sample cross-correlation (parabolic peak) of the timing reference, or the direct arrival
   without one, then averaged coherently in time. A repeat is rejected if its coherence with the
   median repeat is below 0.9 or its 200 Hz–5 kHz level differs by more than 1 dB. Residual drift
   (slope of reference arrivals across repeats) is reported in ppm, with a warning above 20 ppm.
6. **One capture path.** `MultichannelCalibrationTransport` and its targeted bridge become the
   measurement capture path, generalised to K inputs (mics plus optional loopback) and to a
   per-pass two-channel program (sweep on the measured channel, reference chirp on the reference
   channel). The stereo `RoomCorrectionCalibrationTransport` is untouched and serves flag off.
7. **RTA and SPL** need audio while music or the generator plays, so they use an input-only
   monitor IOProc on the mic device (no aggregate, no output), feeding an SPSC ring read by an
   analysis worker. RTA: FFT with band aggregation into IEC 61260-1 base-10 bands at 1/1, 1/3,
   1/6, 1/12, 1/24 and 1/48 octave; exponential or infinite averaging; mic calibration applied.
   SPL: A, C and Z weighting per IEC 61672-1 as double-precision IIR designed per rate; Fast
   (125 ms), Slow (1 s), Leq and C-peak. Calibration by an acoustic calibrator (94 or 114 dB at
   1 kHz) or a mic sensitivity value; uncalibrated readings are labelled "dB (relative)".
   Logger writes CSV to the app container.
8. **Generator** is a `libn60core` graph source stage (graph ABI bump), so it reaches the
   speakers through the same path as music, always before protection. Swift publishes it through
   the normal snapshot; the engine never reads the flag. Signals: white, pink, band-limited
   (octave, third-octave or user range), sine tone, and FFT-length periodic pink for the RTA.
   It replaces program audio on the selected lanes and mutes the others by default. Level
   default −20 dBFS RMS, ceiling −6 dBFS RMS, 100 ms ramps, auto-stop after 10 minutes, stops on
   output change (owner accepted these defaults, 24 Oct 2026). Noise is seeded and resets on start.
9. **Analyses on an impulse response** (all offline, in core):
   - Distortion: H2–H5 from the harmonic impulses, windowed to half the gap to the next harmonic,
     plotted against the fundamental, with THD; the minimum sweep length for clean separation is
     computed and shown.
   - RT60: causal IEC 61260-1 class 1 band filters (double), Schroeder backward integration with
     Lundeby truncation and noise compensation; EDT, T20, T30 per octave and third-octave band,
     with a flag when the band's decay range is too small.
   - Waterfall/CSD: fixed-end windows stepped from the direct arrival, half-Hann rise, 1/24-octave
     smoothing; defaults 0.3 ms × 40 slices (speaker) or 20 ms × 30 (room).
   - Spectrogram: STFT of the IR, Hann, selectable length, 75 % overlap, rendered off the main
     thread to an image.
10. **Library.** `MeasurementLibrary` in the sandbox container
    (`Application Support/NotchSixty/Measurements/`): an index JSON (schema 1) and one folder per
    record with `record.json` (name, notes, group, tags, rate, channel, seat, mic, sweep and timing
    settings, calibration, quality) and `ir.wav` / `raw.wav` as float32. Up to 8 overlays, one
    reference for A/B (difference curve with selectable smoothing). Room-correction positions are
    not migrated; "Use in Room Correction" copies a record into the project.
11. **Formats.** Import and export REW text (`*` comments; frequency, SPL, phase in degrees), FRD,
    ZMA, and WAV impulse responses. Tolerant parsing (tabs, commas, spaces), dot decimal, 1 MB
    limit. Imported curves without an IR support overlays and A/B only.
12. **UI.** A new `measurements` section in the System group behind the flag, with tabs Sweep,
    RTA & SPL, Generator, Analysis and Library. E12 later merges it into the System area. Plots use
    Swift Charts for curves and Canvas for waterfall and spectrogram; no new dependency.
13. **Reference lab.** A deterministic synthetic room in `core/tests` (and reachable from XCTest):
    a known IR (modal sum plus an exponential diffuse tail with set per-band RT60), a polynomial
    nonlinearity with set H2–H5 levels, latency, clock drift in ppm, and seeded noise. Every DSP
    test runs it at 44.1, 48, 88.2, 96, 176.4, 192, 352.8 and 384 kHz.

## Feature flag

`e11.measurement-suite` ("Measurement suite", epic E11) was added to `FeatureFlag.all` in S1 and
removed in S10 (this PR). The suite is always on: `FeatureFlag.all` no longer lists it, the Swift
float-DFT deconvolution branch and the `useMeasurementCore` plumbing are gone, and `MeasurementCore`
does all deconvolution. The generator stage is published through the snapshot like any other stage.
