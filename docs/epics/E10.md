# E10 Mixed-phase room correction and bass control

**Status:** Merged: plan (#223), S1 to S6 (#224 to #229). S7 `e10/joint-bass-apply` (#pending, needs-owner) is open. Next: S8 `e10/verify-and-deploy` (needs-owner). Open owner decision: none.

## Goal

Room correction that beats minimum-phase in blind ABX at three or more seats (gate G3). It corrects
excess phase where it is coherent across seats, keeps pre-ringing and latency within stated
limits, and keeps minimum-phase as a low-latency / video mode. It optimises bass jointly across
mains and subwoofers (Dirac Bass Control class), offers a target editor with curtains, per-channel
offsets and a saved library, and deploys only through prediction plus post-apply measurement. It
works on any layout and at every rate from 44.1 to 384 kHz. The software is done when every slice
passes its reference-lab tests. The ABX is run on the bench in E22.

## What exists today

- **Research designer ("PR129")**: `MixedPhaseResearchDesigner` (`NotchSixty/Audio/OptionalAcousticResearch.swift:43`).
  It blends a symmetric linear-phase share (0–0.4) into an existing minimum-phase FIR pair under a
  0–30 ms latency budget, then audits the taps for deviation, peak gain and pre-ringing energy. It
  is not excess-phase correction. `canDeploy` is hard `false` (:34). Its UI is
  `ProductionOptionalAudioResearchWorkspace.swift:251` and its tests are `OptionalAudioResearchTests.swift`.
- **Production designer**: `RoomCorrectionFIRDesigner` (`NotchSixty/Audio/RoomCorrectionFIRDesigner.swift:49`).
  It produces a minimum-phase FIR by real cepstrum (:211), at a single rate, for left and right
  only, in Swift on Accelerate. `deploymentFilter()` (:384) embeds the headroom.
  `RoomCorrectionDesignPredictionVerifier` (:554) needs confidence ≥ 0.70 (:557) and stored
  prediction agreement within 0.75 dB (:564).
- **Deploy**: `RoomCorrectionProjectController.deploySelectedDesign()` (`NotchSixty/State/RoomCorrectionProjectController.swift:577`)
  re-verifies before it commits. Nothing measures after apply.
- **Multi-seat**: positions carry a weight (`ProductProfiles.swift:2318`). `aggregate` (:37, :86–125
  of the controller) takes a weighted mean of the dB magnitudes and drops phase.
- **Data**: `RoomCorrectionDesign` (`ProductProfiles.swift:2360`) has one `sampleRate`.
  `RoomCorrectionFilter` (`AudioIOEngine.swift:643`) holds left/right taps, and
  `validateSampleRate` throws on any rate mismatch, so a design stops working when the device
  rate changes.
- **Targets**: two built-ins, `.flat` and `.bassShelfAndTilt` (`RoomCorrectionTargetDesigner.swift:56`),
  custom point curves (`ProductProfiles.swift:2340`), `IntelligentRoomTargetGenerator` (:321), and
  import/apply in `ProductionRoomCorrectionWorkspace.swift:1159–1242`. There are no curtains,
  per-channel offsets or library.
- **Graph**: `N60_STAGE_ROOM_FIR` (`core/include/n60/graph.h:74`) follows the Program FIR rules:
  uniform 256-frame partitions, at most 32,768 taps (:282–283), taps identical on the selected
  lanes. That is 85 ms at 384 kHz, too short for bass. It sits at position 14, after BASS_MGMT
  (`UnifiedGraphProgramDSP.swift:396`), so it can address sub lanes. Swift adds it only for stereo
  (`UnifiedGraphConfiguration.swift:278`). The legacy convolver allows 262,144 taps
  (`NotchSixty/Audio/Realtime/N60Convolution.h:35`).
- **Bass**: the BASS_MGMT stage has live crossover, sub gain and polarity (`graph.h:205` ff;
  `core/src/stages_system.cpp:138–314`). `CoherentSubwooferAlignment*` and
  `CoherentMultiSubwooferAlignment*` align subs only. Their post-apply verifier
  (`CoherentMultiSubwooferAlignmentPostApplyVerification.swift:85`) is the only path where
  `canDeploy` is ever true. `MultichannelCalibrationDesigner.swift:68` applies cut-only PEQ
  (boost 0, cut 10 dB, :188).
- **From E11**: `MeasurementCore.swift:8`, multi-mic seat records (`MeasurementMultiMic.swift:50`),

- No latency mode, video mode or lip-sync setting exists. Flags: `FeatureFlag.all` (`NotchSixty/State/FeatureFlags.swift:21`).

## Design note

1. **Where the maths lives.** New design maths is written in C++20 in `libn60core`, under
   `core/src/correct/`, behind `core/include/n60/correct.h` with `N60_CORRECT_ABI_VERSION 1`. This is
   E21's "room-correction FIR and target design" item. It runs offline only: it may allocate,
   never throws across the C boundary, uses no threads, has a fixed summation order, and uses the
   E11 offline FFT. The Swift wrapper is `RoomCorrectionCore.swift`. The minimum-phase designer is
   ported to core with parity, so both modes share one pipeline. The Swift designer serves flag-off
   only and is deleted with the flag.
2. **Pipeline per channel.** The inputs are E11 impulse responses, one per seat.
   - Frequency-dependent window (FDW): a Tukey window centred on the direct arrival whose width is
     a constant number of cycles. The default is 15 cycles below 200 Hz, falling log-linearly to 5
     cycles at 20 kHz, evaluated on a 1/48-octave log grid by per-frequency windowed DFT
     (deterministic and cheap).
   - Magnitude: a weighted power average across seats. The boost limit is reduced where the
     seat-to-seat spread exceeds 6 dB.
   - Excess phase per seat: φ_ex = φ_FDW − φ_min(|H_FDW|), after the pure delay is removed by a
     linear-phase fit from 100 Hz to 1 kHz.
3. **Multi-seat coherence.** R(f) = |Σ wᵢ e^{jφᵢ}| / Σ wᵢ.
   - The applied phase correction is −arg(Σ wᵢ e^{jφᵢ}) × g(R), where g ramps from 0 at R = 0.6 to
     1 at R = 0.8.
   - It applies only below the phase limit: default 500 Hz, user range 100 Hz to 2 kHz.
   - Above that limit, and wherever R is low, the correction is minimum-phase.
   - Seat weights default to 1 with the main seat at 2. Each seat's coherence contribution is shown
     in the UI.
4. **Latency budget and pre-ringing.** Two modes:
   - **Music (mixed-phase)**: the budget L is 20, 50 (default) or 100 ms. The correction impulse is
     delayed by L and its pre-response is tapered to fit.
   - **Low latency / video (minimum-phase)**: about 5 ms added at every rate (open question 2).
   - Pre-ringing limit: in each third-octave band, the predicted corrected response at the main seat
     must stay below −30 dB of the band peak for t < −max(2 ms, 2/f). A design that fails is blocked
     with the band named, never clipped silently.
   - The declared latency goes into the graph's latency report. Switching mode publishes a new
     snapshot through the normal FIR crossfade.
5. **Long filters at every rate: two-band ROOM_FIR** (open question 1).
   - ROOM_FIR gains an optional low band: a second tap set run at fs/D, where D ∈ {1, 2, 4, 8, 16, 32}
     is chosen so that fs/D is 11.025 or 12 kHz.
   - The low band uses linear-phase polyphase half-band decimation and interpolation and is summed
     in parallel with a short full-rate FIR. The full-rate FIR is at most 8,192 taps at 384 kHz,
     about 21 ms.
   - The designer solves the low band as the target minus the full-rate band minus the known
     resampler response, so the sum is exact within the stated error.
   - The two paths are aligned to one declared latency. There is no allocation on the audio
     thread.
   - The stage is built with E20 multirate reuse in mind.
   - The engine never reads the flag.
6. **Every rate and every channel.** A design is stored rate-independent: a complex correction on
   the log grid plus its parameters (design schema 2, with schema 1 migrated as minimum-phase). Taps
   are synthesised off the realtime thread for the current device rate when the design is activated
   and when the rate changes, and the result is cached per rate (as HRIRs are). Correction above
   the measurement Nyquist is unity. Designs cover any E6 layout, with one ROOM_FIR stage per
   distinct tap set using lane masks, including sub lanes. With `e6.legacy-kernel` on, E10 designs
   are refused with a reason, and stereo minimum-phase works as today.
7. **Joint bass optimisation.** Inputs: the measured IR of every main and sub at K seats, timing
   tier (a) or (b) from E11 (a design without it is blocked, since inter-channel delay is needed),
   and the analytic BASS_MGMT crossover response. There are two steps, both deterministic:
   - (i) Per-channel delay, gain and polarity by a grid search plus Levenberg–Marquardt from fixed
     starts.
   - (ii) A per-channel low-frequency FIR (20 Hz to crossover + 1 octave) by weighted regularised
     least squares over seats per bin: min Σₖ wₖ |Σₙ Hₖₙ Xₙ − T|² + λ Σ |Xₙ|², with |Xₙ| capped at
     +6 dB boost and headroom computed. It is then made causal within the latency budget.

   The output is static filters, delays and gains merged into each channel's ROOM_FIR and the
   BASS_MGMT and DELAY parameters. It is not active decay cancellation; that is E19's MIMO
   treatment (open question 3).
8. **Target editor.**
   - Each channel has low and high curtains, outside which the correction returns to unity over a
     third-octave raised-cosine transition.
   - "Limited range" is a preset class that sets the high curtain (default 300 Hz) for bass-only
     correction.
   - Per-channel offsets are level (dB) and tilt (dB/oct) relative to the shared target.
   - The library is `Application Support/NotchSixty/Targets/` (index plus one JSON per target,
     schema 1), with built-ins, duplicate, rename, and import/export through E11's REW text format.
9. **Verification and `canDeploy`.**
   - A mixed-phase or joint-bass design has `canDeploy == false` until both checks below pass.
   - (a) Prediction: the existing verifier, extended with per-seat phase, pre-ringing and latency
     checks, passes.
   - (b) Post-apply: a trial apply keeps the previous configuration ready, and the E11 generator
     plays a synchronised ESS through the live graph while the input monitor captures the mic.
     Timing comes from the E11 acoustic chirp.
   - Post-apply acceptance at the main seat and any seats the user re-measures: 1/6-octave magnitude
     within 1.5 dB of the prediction across the correction range, and excess group delay below the
     phase limit no worse than the prediction + 2 ms.
   - Failure, a timeout or a cancel reverts to the previous configuration automatically.
   - Only a passed report sets `canDeploy`, and it is stored with its evidence. Minimum-phase mode
     keeps today's prediction-only path.
10. **ABX.** A blind A/B/X tool compares two designs. Both are prepared and kept warm, levels are
    matched within 0.1 dB at 500 Hz–2 kHz, and latency is matched by delaying the shorter one. Each
    switch uses the FIR crossfade. Trials are logged to the app container with a binomial p-value.
    This is for the E22 bench and E18.

## Feature flag

`e10.mixed-phase-correction` ("Mixed-phase room correction", epic E10) is added to `FeatureFlag.all`
in S1 and removed in S9. It covers the correction core, both modes, two-band publishing, the target
editor, joint bass and verification. With the flag off, room correction is exactly today's stereo
minimum-phase flow.
