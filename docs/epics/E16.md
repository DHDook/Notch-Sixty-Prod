## Goal

Notch Sixty can be driven without its window: App Intents and Shortcuts, global hotkeys, media-key
volume on outputs with no hardware volume, a richer menu bar remote, a Control Centre control and
desktop widget (tier 1), and a local authenticated REST and websocket API, off by default (tier 2).
Nothing in this epic arms live ANC or MIMO treatment, and nothing changes the selected output.

Out of scope (owner, 11 Nov 2026): the iPhone remote and iPhone as a measurement microphone moved
to V2-4 in `docs/V2_ROADMAP.md` ("Post-v1: iPhone companion app" in the program plan). v1 keeps the
API usable by that future client: documented, versioned, with a pairing a phone can complete.
MIDI and OSC control are not planned (owner, 17 Nov 2026).

## Design note

1. **One command path.** A main-actor `ControlService` (new, `NotchSixty/Automation/`) takes a
   `ControlCommand` (select system, select preset, set or step volume, mute, bypass, processing
   on or off, room correction on or off, read status) and returns `ControlResult` (done, or refused
   with a plain reason). Intents, hotkeys, media keys, the widget and the API all call it; the remote
   panel calls it for the controls S1 adds. It calls the same entry points as the UI, so existing
   rules (Safe Launch, disarm on output change, `outputChangeRequiresIdle`, E15 follow, and E30's
   maximum-level limit once built) apply once, unchanged. It never calls `LiveTreatmentArm.arm` or
   any output selection; a test proves no command reaches either.
2. **One state snapshot.** `ControlStateSnapshot` (Codable, versioned): processing, bypass, room
   correction, volume level, mute, control mode, output name and UID, system and preset IDs and
   names, Quiet Zone and Room Treatment status as read-only text. Published on change, coalesced to
   at most 10 per second. The API websocket, the widget file and intent results read it.
3. **Quiet Zone.** No command arms, starts or stops live ANC or MIMO. The one Quiet Zone intent,
   "Open Quiet Zone", brings the app forward on Active Acoustics with readiness shown; Turn On stays
   the user's click in the app (Q2). Commands that already disarm in the UI (processing off, output
   loss) disarm the same way.
4. **Profiles and output.** Selecting a Playback System bound to another output is refused with
   "This system is for <device>; choose it in Notch Sixty" (selected output stays authoritative,
   `AGENTS.md` section 3). While following (E15), it applies to the current device and does not
   rebind. Every command is reported to the E15 scheduler as a manual change.
5. **Volume.** Commands use the existing level range and the existing hardware or `.softwareDSP`
   path; E16 adds no volume stage and no DSP. Media keys keep the listen-only tap (no Accessibility
   permission, no key suppression); S2 adds the mute key and Option-Shift quarter steps, and moves
   the monitor out of `AudioIOEngine` into `VolumeKeyController` (the engine file gets shorter).
6. **Hotkeys.** Carbon `RegisterEventHotKey` behind `GlobalHotkeyRegistering` (works in the
   sandbox, no permission). Actions: processing, bypass, room correction, next and previous preset,
   volume up, down and mute. None assigned by default (Q5). Conflicts with an existing registration
   are refused with the reason. Stored as key code plus modifiers in `UserDefaults`.
7. **Widget and control.** New target `NotchSixtyWidgets` (WidgetKit extension): a Control Centre
   control set (processing, mute, room correction, preset picker) and a small and medium desktop
   widget (profile, volume, mute, correction, with buttons). Its intents run in the app process
   (the extension never touches audio). Displayed state comes from a snapshot file the app writes
   atomically to a new app group `$(TeamIdentifierPrefix)group.notchsixty.shared`; the E36 driver
   group stays separate. No Quiet Zone or MIMO control.
8. **Local API.** Network.framework only, no dependency. One `NWListener`; an in-house HTTP/1.1
   parser limited to `GET`/`POST`, 16 KB requests, no chunked bodies; websocket via
   `NWProtocolWebSocket` for state events. Paths under `/v1/`; the version is in every response;
   additive changes keep `v1`. Spec in `docs/LOCAL_API.md` (written in S4, extended in S5).
   - Off by default. On binds `127.0.0.1` and `::1` only. "Allow devices on this network" (S5,
     second switch, off) binds all interfaces, advertises `_notchsixty._tcp` by Bonjour and serves
     TLS only.
   - Auth: every request needs `Authorization: Bearer <token>`. Tokens are 256-bit random, shown
     once, stored as SHA-256 hashes in the app's Keychain, named and revocable in Settings.
   - Pairing (S5): the app shows a 6-digit code (valid 2 minutes, five tries, then a new code) and
     a QR with host, port, code and the TLS certificate's SHA-256 fingerprint. A client pins the
     fingerprint and exchanges the code for a token. The self-signed certificate (P-256) is made on
     first LAN enable with an in-house DER encoder and kept in the Keychain.
   - Limits: 20 requests per second per token, 4 websocket clients, idle sockets closed after
     5 minutes. The listener stops when the switch is off and on quit.
9. **Flag-off and release.** Intents are compiled into every build (App Intents metadata is
   static) and refuse with "Not available in this build" while `e16.automation` is off. The
   `AppShortcutsProvider` (Spotlight and Siri phrases) lands only in S6, so nothing shows unasked
   before graduation (Q1). The widget target is embedded; while off it shows "Turn on in Notch
   Sixty" and its intents refuse.
10. **Realtime.** No change to the audio callback, the graph or `core/`. All new code is Swift in
   the app shell. No DSP maths, so no acoustic reference-lab case. Commands that rebuild the graph
   (system or preset) are tested at the eight standard rates against the fake engine.

## Feature flag

`e16.automation` (tier 1: intents, hotkeys, media-key additions, remote additions, widget) and
`e16.local-api` (tier 2), both off by default. Off: intents refuse, no hotkeys registered, today's
media-key behaviour, today's remote, no API settings and no listener. Two flags so the API can be
switched off alone with `-NotchSixtyFeatures -e16.local-api`. S6 graduates both; removal is FC.
Graduating never turns the API on and never arms anything.
